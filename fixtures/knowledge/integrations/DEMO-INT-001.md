# ARIS → Catalog: обзор потока (демо)

> Синтетический демо-документ: описывает вымышленную учебную модель, не системы банка.

## Назначение

Поток запускается **каждые 6 часов** и переносит процессные метаданные из условного источника ARIS
(`SYS-ARIS`) в Data Catalog (`SYS-CAT`) пакетами (batch) по **500 записей**. Запуски идут в 00:00, 06:00, 12:00
и 18:00 (условное время). Цель — чтобы каждый бизнес-процесс учебной модели можно было найти в каталоге вместе
с владельцем, путём в иерархии моделей и состоянием жизненного цикла. Поток инкрементальный (incremental): за
запуск передаются только объекты, изменённые после предыдущего успешного запуска.

Поток заменяет устаревшую ночную полную выгрузку ARIS в 03:00 (DEMO-INT-018, статус deprecated). Полная
выгрузка раз в сутки переписывала весь каталог процессов: изменения доходили до потребителей почти через
сутки, а сбой одной ночи оставлял каталог без обновления на двое суток. Инкрементальная схема удерживает
актуальность каталожных метаданных в пределах 24 часов даже при одном пропущенном запуске.

## Источник и получатель

| Роль | Система | Код | Комментарий |
|---|---|---|---|
| Источник | ARIS (условная модель) | `SYS-ARIS` | процессные модели и объекты, профиль [[DEMO-SRC-002]] |
| Получатель | Data Catalog | `SYS-CAT` | каталог активов, профиль [[DEMO-SRC-007]] |
| Владелец потока | `demo-integration-team` | — | сопровождение, изменения, разбор ошибок |

Со стороны каталога за содержание активов отвечает стюард данных (Steward), со стороны источника — владелец
модели (Owner). Поток только читает ARIS и только пишет в каталог.

## Входные данные (Inputs)

Из ARIS читается выгрузка в формате JSON Lines (одна строка на объект) с шестью полями:

- `aris_object_guid` — идентификатор объекта процесса в ARIS;
- `aris_object_name` — название процесса;
- `aris_model_path` — путь объекта в иерархии моделей;
- `aris_owner_role` — роль владельца процесса;
- `aris_last_change` — момент последнего изменения объекта;
- `aris_status` — статус объекта: `released`, `in_work` или `obsolete`.

Окно выборки задаётся водяным знаком `aris_watermark` — это максимальное значение `aris_last_change` в
последнем принятом пакете. В запуск попадают объекты, у которых `aris_last_change` строго больше водяного
знака. Водяной знак сдвигается только после того, как пакет принят каталогом.

## Выходные данные (Outputs)

В каталоге создаётся или обновляется актив класса BusinessProcess с полями `process_id`, `process_name`,
`process_path`, `owner_role`, `source_changed_at`, `lifecycle_state` и техническим полем
`source_system = SYS-ARIS`. Каждый запуск также оставляет отчёт запуска: число прочитанных, принятых и
отклонённых записей, коды ошибок и новое значение водяного знака.

## Правила преобразования (Transformation Rules)

Обработка одного пакета идёт в фиксированном порядке:

1. Выборка до 500 изменённых объектов по водяному знаку.
2. Проверка ограничений (DEMO-INT-003): обязательные поля, глубина иерархии, статус, доля прошедших записей.
3. Маппинг полей (DEMO-INT-002), включая перевод `aris_object_guid` в `process_id` через таблицу
   соответствия `MAP_ARIS_PROCESS`.
4. Отбрасывание повторов по ключу идемпотентности `source_system + source_object_id + source_changed_at`:
   повтор в пределах 72 ч второй раз не записывается.
5. Запись принятых записей в каталог и сдвиг водяного знака.

Если изменённых объектов больше 500, запуск обрабатывает несколько пакетов подряд, но не более 40 пакетов
(20 000 записей) за один запуск. Остаток забирает следующий запуск по расписанию.

## Ограничения (Constraints)

- Обратная запись в ARIS не выполняется. Полная повторная выгрузка всего репозитория возможна только по
  заявке владельца источника и не является штатным режимом.
- Удаление объекта в ARIS не удаляет актив каталога: объект со статусом `obsolete` отклоняется валидацией,
  а судьбу актива решает стюард по политике архивирования.
- Расписание утверждено в документе о расписаниях обновления метаданных (DEMO-INT-013). Почасовой запуск,
  предложенный в проекте следующей версии расписания, не утверждён и не применяется.
- Содержимое моделей (диаграммы, вложения, описания шагов) не передаётся — только шесть полей метаданных.
- Для потока не определён SLA; шестичасовой цикл — это расписание, а не обязательство об уровне сервиса.

## Ошибки и обработка (Error Cases)

| Код | Ситуация | Обработка |
|---|---|---|
| `E-SRC-003` | ARIS недоступен | до 5 повторных попыток с экспоненциальной задержкой, затем сообщение в `dlq.metadata.v1`; водяной знак не сдвигается |
| `E-VAL-002` | пакет не прошёл валидацию | пакет целиком уходит в карантин `q_aris_rejected` (DEMO-INT-003) |
| `E-MAP-001` | GUID нет в `MAP_ARIS_PROCESS` | запись не пишется в каталог; повторы по общей политике (таблица может пополниться между попытками), затем `dlq.metadata.v1`; соответствие добавляет владелец источника (DEMO-INT-002) |

Пропущенный запуск отдельно не догоняется: следующий запуск по расписанию забирает все изменения после
водяного знака, в пределах лимита 40 пакетов.

## Пример

Запуск 2026-10-14 в 12:00 (условное время). Водяной знак после запуска 06:00 — `2026-10-14T05:41:00Z`.
С этого момента в ARIS изменено 730 объектов, поэтому запуск обрабатывает два пакета. Среди них — объект
процесса «Согласование заявки (демо)», изменённый в 09:12 по местному времени (06:12 UTC):

```yaml
run: aris-catalog 12:00
batches:
  - size: 500        # прошло 488 записей (97,6 %), пакет принят, 12 записей отклонено
  - size: 230        # прошло 229 записей, пакет принят, 1 запись отклонена
example_record:
  aris_object_guid: "guid-demo-0417"
  aris_object_name: "Согласование заявки (демо)"
  aris_last_change: "2026-10-14T09:12:00+03:00"
  aris_status: released
catalog_asset:
  process_id: PRC-000417
  lifecycle_state: active
  source_system: SYS-ARIS
```

## Связанные документы

- **DEMO-SRC-002** (`consumes`) — профиль источника ARIS: откуда берутся шесть полей экспорта, которые читает поток.
- **DEMO-SRC-007** (`produces`) — Data Catalog: поток создаёт и обновляет в нём активы бизнес-процессов.
- **DEMO-INT-018** (`supersedes`) — устаревшая ночная полная выгрузка ARIS в 03:00; заменена этим инкрементальным
  потоком и переведена в статус deprecated.
- **DEMO-INT-002** (ссылка) — подробный маппинг полей, который выполняется на шаге 3.
- **DEMO-INT-003** (ссылка) — валидационные ограничения шага 2, правило 95 % и карантин `q_aris_rejected`.
- **DEMO-INT-013** (ссылка) — утверждённое расписание: ARIS → Catalog каждые 6 часов.
- **SEM-INT-ARIS-001** (ссылка) — ранняя discovery-заметка (черновик) с открытыми вопросами об ARIS.
