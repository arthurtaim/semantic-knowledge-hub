# ARIS: валидационные ограничения (демо)

> Синтетический демо-документ: описывает вымышленную учебную модель, не системы банка.

## Назначение

Документ определяет, какие записи ARIS допускаются к маппингу (DEMO-INT-002) и записи в Data Catalog, и что
происходит с пакетом, в котором слишком много дефектных записей. Ограничения (constraints) защищают каталог
и производный от него датасет Process Overview (DEMO-SEM-009) от неполных и некорректных процессных метаданных.

## Источник и получатель

Проверки выполняются в потоке ARIS → Catalog над записями `SYS-ARIS` до маппинга. Результат проверки получают:
маппинг — только прошедшие записи; карантин `q_aris_rejected` — отклонённые записи или пакет целиком;
Data Quality Monitor (`SYS-DQM`) — метрика `aris_batch_pass_rate` (доля прошедших записей пакета).

## Входные данные (Inputs)

- Пакет до 500 записей с полями `aris_object_guid`, `aris_object_name`, `aris_model_path`, `aris_owner_role`,
  `aris_last_change`, `aris_status`.
- Константы конфигурации: `ARIS_MAX_DEPTH = 7`, порог пакета 95 % (`ARIS_MIN_BATCH_PASS`).

## Выходные данные (Outputs)

- Набор прошедших записей — передаётся маппингу.
- Отклонённые записи с кодом `E-VAL-002` и причиной — в `q_aris_rejected` с признаком `scope: record`.
- Решение по пакету: «принят» или «в карантине»; во втором случае весь пакет попадает в `q_aris_rejected`
  с признаком `scope: batch`, и в каталог из него ничего не пишется.

## Правила преобразования (Transformation Rules)

Валидация не меняет значения полей, она только принимает или отклоняет. Правила проверки:

1. **Обязательные поля**: `aris_object_guid`, `aris_object_name`, `aris_owner_role` должны быть непустыми после
   удаления пробелов по краям. Причина отказа — `missing_field`.
2. **Глубина иерархии**: число уровней в `aris_model_path` не больше `ARIS_MAX_DEPTH = 7`. Путь из 8 уровней
   отклоняется с причиной `depth_exceeded`; путь не обрезается.
3. **Статус**: записи с `aris_status = obsolete` отклоняются с причиной `status_obsolete`.
4. **Правило пакета**: пакет принимается, только если проверки прошли **не менее 95 %** его записей (порог
   полноты по умолчанию из DEMO-GOV-003). Иначе весь пакет уходит в карантин `q_aris_rejected`. Доля считается
   без округления вверх: 475 из 500 = 95,0 % — пакет принят; 474 из 500 = 94,8 % — пакет в карантине.

## Ограничения (Constraints)

- Порог 95 % действует на уровне пакета интеграции. Для датасета Process Overview (DEMO-SEM-009) стандарт
  полноты задаёт более строгое правило своей области: **98 %** заполненности атрибутов `process_id`,
  `process_name`, `owner_role`. Это разница областей применения, а не противоречие: пакет с долей 96 % проходит
  интеграционную проверку, но датасет после загрузки может не достичь 98 % и тогда считается не
  соответствующим требованиям качества.
- Три атрибута правила 98 % получаются из обязательных полей ARIS: `process_id` — из `aris_object_guid`,
  `process_name` — из `aris_object_name`, `owner_role` — из `aris_owner_role`. Поэтому эти поля и сделаны
  обязательными на входе.
- Валидация ничего не исправляет: не подставляет значения по умолчанию и не сокращает пути.
- Изменение `ARIS_MAX_DEPTH` или порога пакета возможно только через ревью этого документа; ужесточение
  правила считается несовместимым изменением и повышает MAJOR-версию.

## Ошибки и обработка (Error Cases)

- **`E-VAL-002` (validation failed)** — код из общего перечня интеграционных ошибок (DEMO-INT-011).
  Повторные попытки по нему не выполняются: повтор той же записи даёт тот же результат.
- **Запись отклонена в принятом пакете** — запись остаётся в `q_aris_rejected` (`scope: record`) до разбора
  стюардом источника (роль `src-steward-aris`). После исправления в ARIS объект получает новое `aris_last_change` и приходит в следующем запуске.
- **Пакет в карантине** — водяной знак потока не сдвигается, следующий запуск снова читает те же объекты.
  Если источник не исправлен, пакет снова уходит в карантин, а стюард получает повторное уведомление.

## Версия и статус

Версия 1.2, статус approved, дата проверки 2026-10-20. В 1.2 (MINOR) добавлено явное пояснение о разнице
областей правил 95 % и 98 %. В 1.1 введены признаки `scope: record` и `scope: batch` в карантине.

## Пример

Пакет из 500 записей: у 12 нет `aris_owner_role`, у 6 путь глубиной 8 уровней, 4 записи со статусом
`obsolete`. Отклонено 22, прошло 478 — это 95,6 %, пакет принят, 22 записи лежат в карантине как `scope: record`.

Другой пакет из 500 записей с 31 отказом:

```yaml
quarantine: q_aris_rejected
error_code: E-VAL-002
scope: batch
batch_size: 500
passed: 469
pass_rate: "93,8 %"
threshold: "95 %"
reasons: {missing_field: 17, depth_exceeded: 9, status_obsolete: 5}
```

Доля 93,8 % ниже порога, поэтому в каталог не попадает ни одна запись этого пакета.

- **DEMO-SEM-009** (`constrains`) — проверки ограничивают, какие процессные метаданные попадают в датасет
  Process Overview; сам датасет дополнительно требует 98 %.
