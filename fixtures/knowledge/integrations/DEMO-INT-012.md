# Idempotency и дедупликация

> Синтетический демо-документ: описывает вымышленную учебную модель, не системы банка.

## Назначение

Документ определяет, как потоки метаданных учебной модели распознают повторно доставленные сообщения и
не применяют их дважды. Повторная доставка возможна при CDC через Event Hub, при повторных попытках после
ошибок и при ручной повторной отправке сообщений из DLQ. Идемпотентность (idempotency) означает, что
повторное применение одного и того же изменения не меняет результат.

## Источник и получатель

Правила действуют для всех потоков: ARIS → Catalog, CATIA → Catalog, CRM → MDM, ERP → Semantic Layer.
Реестр обработанных ключей ведёт обработчик каждого потока на стороне получателя.

## Входные данные (Inputs)

Каждое сообщение или запись пакета обязано содержать три поля, из которых строится ключ:

| Поле | Смысл | Пример для ARIS |
|---|---|---|
| `source_system` | код системы-источника | `SYS-ARIS` |
| `source_object_id` | устойчивый идентификатор объекта в источнике | значение `aris_object_guid` |
| `source_changed_at` | момент изменения объекта в источнике | значение `aris_last_change` |

Для CATIA `source_object_id` — это `catia_part_number`. Для ERP при полной перезагрузке
`source_changed_at` — время снимка, общее для всех строк снимка.

## Выходные данные (Outputs)

Решение по сообщению: «применить» (ключ новый) или «отбросить как дубликат» (ключ уже зафиксирован).
Отброшенные дубликаты не считаются ошибкой и не попадают в DLQ; обработчик ведёт только их счётчик.

## Правила преобразования (Transformation Rules)

1. Ключ идемпотентности (idempotency key) = `source_system + source_object_id + source_changed_at`.
   Части соединяются через разделитель `|`.
2. Перед расчётом ключа `source_changed_at` приводится к UTC в формате ISO 8601 с точностью до секунды.
3. Ключ фиксируется в реестре только после успешного применения сообщения.
4. Сообщение, ключ которого уже есть в реестре, отбрасывается, если ключ зафиксирован не более 72 ч назад.
   Через 72 ч запись о ключе удаляется из реестра.
5. Дубликат старше 72 ч не отбрасывается по ключу, но и не меняет данные: событие со `source_changed_at`
   не новее уже применённого игнорируется по правилу порядка из DEMO-INT-010.

## Ограничения (Constraints)

- Ключ надёжен, только если `source_object_id` детерминирован и не переиспользуется: объект,
  пересозданный в источнике с новым идентификатором, считается новым объектом.
- Два разных изменения одного объекта с одинаковым `source_changed_at` неразличимы для ключа; источник
  обязан выдавать различимое время изменения.
- Дедупликация сообщений не объединяет разные сущности с похожими названиями: это задача правил
  разрешения неоднозначных сущностей, а не этого документа.

## Ошибки и обработка (Error Cases)

- Сообщение без одной из трёх частей ключа отклоняется с кодом `E-VAL-002` без повторов (DEMO-INT-011).
- Если реестр ключей недоступен, обработка считается неудачной с кодом `E-SRC-003` и повторяется по общей
  политике: применять сообщение без проверки ключа запрещено.

## Версия и статус

Версия 1.2, статус approved. Версия 1.2 (MINOR) уточнила правило 5 о дубликатах старше 72 ч.

## Пример

Процесс ARIS с `aris_object_guid = guid-demo-0417` изменён, `aris_last_change` равен
`2026-10-14T09:12:00+03:00`. После приведения к UTC `source_changed_at` = `2026-10-14T06:12:00Z`, и ключ
записи: `SYS-ARIS|guid-demo-0417|2026-10-14T06:12:00Z`. Поток ARIS → Catalog применяет запись в запуске
12:00 и фиксирует ключ. Через 40 минут та же запись повторно отправлена из-за ручного перезапуска: ключ
найден в реестре (прошло меньше 72 ч), запись отбрасывается как дубликат. Если бы первая обработка
завершилась ошибкой `E-SRC-003`, ключ не был бы зафиксирован, и повторная попытка применила бы запись штатно.
