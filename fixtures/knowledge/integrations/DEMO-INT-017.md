# Расписание обновления метаданных v2 — проект

> Синтетический демо-документ: описывает вымышленную учебную модель, не системы банка.

> **Статус: черновик (draft). Документ НЕ действует.** Он предлагает обновлять поток ARIS → Catalog
> каждый час и тем самым противоречит утверждённому расписанию DEMO-INT-013, где этот поток запускается
> каждые 6 ч. До ревью и утверждения действует только DEMO-INT-013; ссылаться на значения из этого
> проекта как на правило нельзя.

## Назначение

Проект предлагает сократить интервал обновления метаданных ARIS в каталоге, чтобы потребители датасета
Process Overview видели изменения процессов быстрее. Остальные потоки утверждённого расписания проект не
затрагивает.

## Источник и получатель

Поток ARIS → Catalog (DEMO-INT-001): источник `SYS-ARIS`, получатель — каталог `SYS-CAT`.

## Предлагаемое изменение

| Поток | Действует сейчас (DEMO-INT-013) | Предлагается в проекте |
|---|---|---|
| ARIS → Catalog | каждые 6 ч: 00:00, 06:00, 12:00, 18:00 | ежечасно, в начале каждого часа |
| CATIA → Catalog | ежедневно в 02:30 | без изменений |
| CRM → MDM | CDC, задержка до 15 мин | без изменений |
| ERP → Semantic Layer | ночью в 01:00 | без изменений |

## Входные данные (Inputs)

- Утверждённое расписание DEMO-INT-013 как базовая версия, от которой отсчитывается изменение.
- Требования актуальности DEMO-GOV-005: проект их не меняет (каталог — 24 ч, Process Overview — 12 ч), а
  только увеличивает запас до их границы.

## Выходные данные (Outputs)

В случае утверждения — новая версия расписания для потока ARIS → Catalog: 24 запуска в сутки вместо 4.

## Правила преобразования (Transformation Rules)

1. Размер пакета ARIS остаётся прежним — 500 записей.
2. Каждый запуск забирает изменения, накопленные с предыдущего запуска.
3. Политика повторных попыток не меняется: полный цикл повторов (15 мин 30 с) укладывается в час.

## Ограничения (Constraints)

- Проект не прошёл ревью и не имеет даты проверки; он не может использоваться как основание для настройки
  потоков или для ответов о действующем расписании.
- Нагрузка ежечасных запусков на источник ARIS не оценена.
- Не определено, что делать, если запуск не завершился к началу следующего часа.

## Ошибки и обработка (Error Cases)

Отдельных правил проект не вводит. Открытые вопросы для ревью:

- может ли сбой одного запуска с повторами накладываться на следующий ежечасный запуск;
- как изменится число сообщений в DLQ при шестикратном росте числа запусков;
- нужно ли отдельное уведомление потребителей о смене частоты.

## Версия и статус

Версия 0.2, статус draft, `reviewed_at` не заполнен. Версия 0.2 добавила таблицу сравнения с действующим
расписанием. Документ станет действующим только после ревью, утверждения и выпуска новой версии
DEMO-INT-013; до тех пор при любом расхождении верно утверждённое расписание.

## Пример

Вопрос «как часто сейчас обновляются метаданные ARIS в каталоге?» имеет ответ из DEMO-INT-013 — каждые
6 ч. Значение «ежечасно» из этого проекта — лишь предложение и в ответе как действующее правило
использоваться не должно.
