# CATIA → Catalog: обзор потока (демо)

> Синтетический демо-документ: описывает вымышленную учебную модель, не системы банка.

## Назначение

Поток ежедневно переносит метаданные изделий (деталей и сборок) из условного источника CATIA (`SYS-CATIA`) в
Data Catalog (`SYS-CAT`). В каталоге каждое изделие становится активом класса BusinessObject, который можно найти
по номеру, ревизии и классу материала, а связи «изделие входит в сборку» передаются маппингу полей
(DEMO-INT-005), который строит из них рёбра датасета Dependency Graph. Запуск — **ежедневно в 02:30**
(условное время).

## Источник и получатель

| Роль | Система | Код | Комментарий |
|---|---|---|---|
| Источник | CATIA (условная модель) | `SYS-CATIA` | метаданные изделий, профиль [[DEMO-SRC-003]] |
| Получатель | Data Catalog | `SYS-CAT` | активы класса BusinessObject, профиль [[DEMO-SRC-007]] |
| Владелец потока | `demo-integration-team` | — | сопровождение и разбор ошибок |

Поток только читает CATIA и ничего не передаёт обратно в источник.

## Входные данные (Inputs)

CATIA отдаёт суточную дельту — CSV с заголовком, разделитель `;`. В неё попадают изделия, у которых после
предыдущего запуска в 02:30 появилась новая ревизия или изменилась ссылка на сборку; обычно это от нескольких
десятков до нескольких сотен изделий. Отдельного размера пакета нет — дельта загружается одним запуском. Поля:

- `catia_part_number` — номер изделия, формат `CP-` + 6 цифр, не переиспользуется;
- `assembly_ref` — номер родительской сборки; пусто у изделий верхнего уровня;
- `revision_letter` — буква ревизии (`A`, `B`, `C` …);
- `material_class` — класс материала из закрытого списка источника (например, `MC-STEEL`, `MC-ALU`).

## Выходные данные (Outputs)

- Актив класса BusinessObject в каталоге — один на каждый `catia_part_number`, с последней ревизией и классом
  материала. Идентификатор актива `catalog_asset_id` присваивает сам каталог.
- Набор связей «изделие → сборка», который передаётся маппингу [[DEMO-INT-005]].
- Отчёт запуска: число строк дельты, созданных, обновлённых и отклонённых активов.
- После успешной загрузки каталог публикует событие `catalog_load_completed`, по которому запускается
  разрешение ссылок в датасетах.

## Правила преобразования (Transformation Rules)

1. Новый номер создаёт актив; изменившиеся ревизия, класс материала или сборка обновляют существующий.
2. Прежняя ревизия не удаляется, а остаётся в истории актива с отметкой «заменена»; номер изделия при новой
   ревизии не меняется.
3. Дельта не сообщает об удалении изделий, поэтому поток активы не удаляет.
4. `assembly_ref` передаётся маппингу без изменений; превращение в рёбра графа выполняет DEMO-INT-005.
5. `material_class` переносится как есть, без перекодировки.
6. Повторная обработка той же строки отбрасывается по ключу идемпотентности
   `source_system + source_object_id + source_changed_at`.

## Ограничения (Constraints)

- Передаются только метаданные: 3D-геометрия, чертежи и файлы моделей в поток не входят.
- `catia_part_number` обязателен; строка без него не принимается.
- `assembly_ref` должна указывать на изделие, известное каталогу или пришедшее в той же дельте.
- Буква ревизии не может «откатиться»: строка с ревизией младше той, что уже есть в каталоге, отклоняется.
- Расписание 02:30 утверждено в документе о расписаниях обновления метаданных (DEMO-INT-013). Метаданные каталога
  должны быть не старше 24 часов, поэтому один неудачный запуск уже означает нарушение актуальности.
- Изменения, сделанные в CATIA после запуска 02:30, видны в каталоге только на следующий день.

## Ошибки и обработка (Error Cases)

| Код | Ситуация | Обработка |
|---|---|---|
| `E-SRC-003` | выгрузка CATIA недоступна | до 5 повторных попыток, затем сообщение в `dlq.metadata.v1`; каталог остаётся в состоянии предыдущих суток |
| `E-VAL-002` | нет номера изделия, откат ревизии, цикл в составе сборки | строка отклоняется без повторов и попадает в отчёт |
| `E-MAP-001` | `assembly_ref` указывает на неизвестное изделие | актив изделия обновляется, связь не создаётся; причина `unknown_assembly` уходит стюарду источника (роль `src-steward-catia`) |

Неизвестная сборка никогда не подбирается по похожему номеру: связь появится, когда сборка придёт из источника.

## Пример

Фрагмент суточной дельты:

```
catia_part_number;assembly_ref;revision_letter;material_class
CP-100010;;B;MC-STEEL
CP-104233;CP-100010;C;MC-ALU
```

```yaml
run: catia-catalog 02:30
result:
  business_object_assets: 2      # активы CP-100010 и CP-104233
  assembly_links_for_mapping: 1  # CP-104233 входит в сборку CP-100010
```

`CP-100010` — изделие верхнего уровня, связь для него не передаётся. Если завтра выйдет ревизия `D` изделия
`CP-104233`, актив останется тем же, изменится только ревизия.

## Связанные документы

- **DEMO-SRC-007** (`produces`) — Data Catalog: поток создаёт и обновляет в нём активы BusinessObject.
- **DEMO-INT-005** (ссылка) — маппинг полей CATIA в BusinessObject и рёбра Dependency Graph.
- **DEMO-INT-013** (ссылка) — утверждённое расписание: CATIA → Catalog ежедневно в 02:30.
