# Контракт атрибута Process ID

> Синтетический демо-документ: описывает вымышленную учебную модель, не системы банка.

## Назначение

Контракт задаёт правила для атрибута `process_id` — устойчивого идентификатора бизнес-процесса в
семантическом слое. Он обязателен для логической модели BusinessProcess (DEMO-SEM-002), физической таблицы
`sl_process_metadata` (DEMO-SEM-005) и для интеграционного маппинга ARIS → Catalog. Цель — чтобы ссылка на
процесс оставалась верной годами, независимо от переименований и переносов в модели ARIS.

## Определение

Process ID — строка формата `PRC-` и ровно 6 цифр, регулярное выражение `^PRC-\d{6}$`. Длина всегда
10 символов, префикс — заглавные латинские буквы, ведущие нули обязательны. Пример: `PRC-000417` —
«Согласование заявки (демо)». Идентификатор выдаётся семантическим слоем, а не вычисляется из
`aris_object_guid`: связь между ними хранится в таблице соответствия `MAP_ARIS_PROCESS`.

## Атрибуты

Таблица соответствия `MAP_ARIS_PROCESS`:

| Атрибут | Тип | Обязательный | Описание | Источник |
|---|---|---|---|---|
| `aris_object_guid` | string | да | Идентификатор объекта в ARIS | Выгрузка ARIS |
| `process_id` | string | да | Выданный Process ID | Регистрация стюардом данных |
| `registered_at` | datetime (UTC) | да | Момент регистрации соответствия | Регистрация |
| `mapping_state` | enum | да | `active` или `retired` | Ведёт стюард данных |

Строки в таблицу добавляет только стюард данных; интеграционный поток её только читает и новых номеров не
выдаёт.

## Связи с другими сущностями

- **Логическая модель.** Атрибут `process_id` сущности BusinessProcess — единственный ключ её
  идентичности.
- **Физическая модель.** Колонка `process_id` — первичный ключ таблицы `sl_process_metadata`; проверка
  `ck_process_id_format` повторяет регулярное выражение контракта.
- **Интеграция.** Маппинг полей ARIS → Catalog переводит `aris_object_guid` в `process_id` поиском в
  `MAP_ARIS_PROCESS`.

## Ограничения

1. **Формат.** Только `^PRC-\d{6}$`. Пробелы по краям не обрезаются: значение с пробелом невалидно.
2. **Неизменяемость.** Process ID не меняется при переименовании процесса, переносе в другую ветку
   (`process_path`), смене роли-владельца или переходе `draft` → `active`.
3. **Без повторного использования.** Когда процесс выводится из обращения (в ARIS он стал `obsolete`),
   строка в `MAP_ARIS_PROCESS` получает `mapping_state = retired`; номер больше никогда не выдаётся.
4. **Один к одному.** Одному `process_id` соответствует не более одной строки `active`, и наоборот. Если
   объект в ARIS пересоздан и получил новый GUID, стюард данных связывает новый GUID с прежним Process ID, а
   старую строку переводит в `retired`; номер процесса не меняется.
5. **Резерв.** `PRC-000000` зарезервирован для тестов и никогда не выдаётся.
6. **Выдача.** Номера выдаются последовательно при регистрации процесса стюардом данных; порядок номеров не
   несёт смысла.
7. **Ошибки.** GUID не найден в `MAP_ARIS_PROCESS` (или найдена только строка `retired`) — ошибка
   `E-MAP-001` (mapping not found): запись отклоняется до регистрации соответствия стюардом. Значение не
   проходит формат — `E-VAL-002` (validation failed). Обе ошибки зависят от данных, поэтому автоматических
   повторов для них нет.

## Пример

| Значение | Результат | Причина |
|---|---|---|
| `PRC-000417` | валидно | `PRC-` и 6 цифр |
| `PRC-417` | невалидно | нужно ровно 6 цифр, ведущие нули обязательны |
| `prc-000417` | невалидно | префикс только заглавными буквами |
| `PRC-0004170` | невалидно | 7 цифр |
| `PRC-000000` | невалидно | зарезервирован, не выдаётся |
| `PRC 000417` | невалидно | вместо дефиса пробел |

Сценарий: процесс «Согласование заявки (демо)» перенесли в ветку «Демо-модель/Обращения» и сменили
роль-владельца. Изменятся `process_path` и `owner_role`, а `process_id` останется `PRC-000417`, и все
ссылки датасетов и потребителей на него продолжат работать.
