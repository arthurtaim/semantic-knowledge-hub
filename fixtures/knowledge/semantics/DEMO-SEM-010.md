# Датасет Dependency Graph

> Синтетический демо-документ: описывает вымышленную учебную модель, не системы банка.

## Обзор

Dependency Graph (`DS-002`) — список направленных рёбер между бизнес-объектами: какая деталь входит в
какую сборку. Датасет нужен для анализа влияния: если меняется сборка, по графу видно, какие детали и
вышестоящие сборки затронуты. Узлы графа — объекты BusinessObject, сами атрибуты объектов в датасет не
копируются.

## Источники

- Условная система CATIA (`SYS-CATIA`) — через поток CATIA → Catalog и маппинг его полей: `catia_part_number`
  с префиксом `SYS-CATIA:` даёт `node_id`, `assembly_ref` с тем же префиксом — `depends_on_node_id`,
  `dependency_type` всегда `assembly`. Для изделия верхнего уровня (пустой `assembly_ref`) строка не создаётся.
- Логическая модель BusinessObject: проверка, что оба конца ребра существуют.

## Бизнес-сущности

BusinessObject (узлы) и связь «входит в сборку» (рёбра), заданная атрибутом `parent_object_id`.

## Атрибуты

| Атрибут | Тип | Обязательный | Описание | Источник |
|---|---|---|---|---|
| `node_id` | string | да | Объект, который входит в сборку (деталь или подсборка), например `SYS-CATIA:CP-104233` | BusinessObject.`object_id` (`SYS-CATIA:` + `catia_part_number`) |
| `depends_on_node_id` | string | да | Сборка, в которую входит объект | BusinessObject.`parent_object_id` (`SYS-CATIA:` + `assembly_ref`) |
| `dependency_type` | enum | да | Тип зависимости из `DICT_DEPENDENCY_TYPE`; в демо только `assembly` | Константа потока CATIA |
| `source_system` | string | да | Код системы-источника, `SYS-CATIA` | BusinessObject.`source_system` |

Ребро направлено **от детали к сборке**. Буква ревизии (`revision_letter`) в датасет не входит: граф
строится только по последней ревизии каждого объекта.

## Правила качества

1. **Без петель.** `node_id` не равен `depends_on_node_id`.
2. **Без циклов.** Для `dependency_type = assembly` цикл (A входит в B, B — в A, прямо или через
   посредников) недопустим; строка, замыкающая цикл, не записывается (ошибка `E-VAL-002` в потоке) и
   разбирается стюардом источника.
3. **Целостность.** Оба конца ребра существуют среди объектов BusinessObject того же `source_system`.
4. **Уникальность.** У узла не более одной строки `assembly`: деталь не входит в две сборки одновременно;
   при смене сборки прежняя строка заменяется новой.
5. **Полнота и актуальность** — по общим порогам: 95 % обязательных атрибутов, данные не старше 24 ч.
   Более строгих правил для этого датасета нет.

## Политика обновления (Refresh Policy)

Полная пересборка раз в сутки после ежедневной загрузки CATIA → Catalog в 02:30 (условное время);
обычно завершается к 03:30. Инкрементального режима нет: граф пересобирается целиком, чтобы проверка циклов
шла по всему набору рёбер.

## Ограничения доступа

- `demo-reader` — чтение датасета.
- `demo-editor` — предложение изменений описания; `demo-approver` — утверждение.

Датасет выдаётся потребителям через Consumer API наравне с Process Overview. Сведений о лицах нет.

## Пример

| `node_id` | `depends_on_node_id` | `dependency_type` | `source_system` |
|---|---|---|---|
| `SYS-CATIA:CP-104233` | `SYS-CATIA:CP-100010` | `assembly` | `SYS-CATIA` |
| `SYS-CATIA:CP-104240` | `SYS-CATIA:CP-100120` | `assembly` | `SYS-CATIA` |
| `SYS-CATIA:CP-100120` | `SYS-CATIA:CP-100010` | `assembly` | `SYS-CATIA` |

Деталь «Кронштейн крепления (демо)» (`CP-104233`, ревизия `C`) входит прямо в изделие верхнего уровня
«Сборка узла крепления (демо)» (`CP-100010`); деталь `CP-104240` входит в подсборку `CP-100120`, а та — в
`CP-100010`. У `CP-100010` строки нет: это изделие верхнего уровня. Если бы в выгрузке появилась строка
`SYS-CATIA:CP-100010` → `SYS-CATIA:CP-104233`, она замкнула бы цикл и не была бы записана по правилу 2.
Новая ревизия `D` детали `CP-104233` не меняет ни одной строки графа: `node_id` от ревизии не зависит.
