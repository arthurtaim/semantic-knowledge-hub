# Датасет Source Coverage

> Синтетический демо-документ: описывает вымышленную учебную модель, не системы банка.

## Обзор

Source Coverage (`DS-003`) показывает, насколько полно каждая система-источник представлена в семантическом
слое. Одна строка — одна система на момент измерения. Датасет отвечает на два вопроса: «сколько объектов
источника уже доступно потребителям» и «какая часть описанных колонок источника сопоставлена с логической
моделью». Это агрегат: записей процессов или объектов в нём нет.

## Источники

- Реестр `MAP_LOGICAL_PHYSICAL` (маппинг логической и физической моделей): строки с состоянием `mapped` или
  `unmapped` по каждой системе.
- Data Catalog (`SYS-CAT`): список систем, зарегистрированных как источники семантического слоя, и число
  их активов, успешно разрешённых в датасеты. Активы с неразрешённой ссылкой не засчитываются.
- Справочник `DICT_SYSTEM_CODE`: допустимые коды систем.

## Бизнес-сущности

Система-источник (по коду из `DICT_SYSTEM_CODE`) и логические сущности, которые она питает: BusinessProcess
(ARIS), BusinessObject (CATIA, ERP).

## Атрибуты

| Атрибут | Тип | Обязательный | Описание | Источник |
|---|---|---|---|---|
| `system_code` | string | да | Код системы, например `SYS-ARIS` | `DICT_SYSTEM_CODE`, список источников из Data Catalog |
| `covered_entities` | integer | да | Число активов системы в каталоге, разрешённых в датасеты (неразрешённые не считаются) | Data Catalog |
| `coverage_pct` | decimal(4,1) | да | Доля строк реестра маппинга системы в состоянии `mapped`, в процентах от 0.0 до 100.0 | Вычисляется по `MAP_LOGICAL_PHYSICAL` |
| `last_measured_at` | datetime (UTC) | да | Момент измерения | Время запуска расчёта |

Формула: `coverage_pct` = (строки системы с `mapping_state = mapped`) / (все строки системы в реестре)
× 100, с округлением вниз до одного знака после запятой. Колонка, для которой нет правила (`unmapped`),
уменьшает покрытие.

## Правила качества

1. `coverage_pct` в диапазоне от 0.0 до 100.0; `covered_entities` не меньше 0.
2. Одна строка на систему на одно измерение: пара (`system_code`, `last_measured_at`) уникальна.
3. `system_code` существует в `DICT_SYSTEM_CODE` и зарегистрирован в Data Catalog как источник
   семантического слоя; системы, которые семантический слой не питают (например, CRM, данные которой идут
   в MDM), строки не получают.
4. Полнота и актуальность — по общим порогам: 95 % и 24 ч. Более строгих правил для этого датасета нет.
5. Если Data Catalog недоступен, измерение не выполняется и предыдущие строки остаются действующими; нулевое
   покрытие из-за недоступности каталога не записывается.

## Политика обновления (Refresh Policy)

Ежедневное измерение в 04:00 (условное время) — после ночной полной загрузки ERP → Semantic Layer
(01:00) и ежедневной загрузки CATIA → Catalog (02:30), чтобы в расчёт попали строки реестра, обновлённые за
ночь. Каждое измерение добавляет новые строки, история хранится 90 дней.

## Ограничения доступа

- `demo-reader` — чтение.
- `demo-editor` — предложение изменений описания; `demo-approver` — утверждение.

Датасет содержит только агрегаты по системам, сведений о лицах и содержимом записей нет.

## Пример

Измерение `last_measured_at` = 2026-10-15T04:00:00Z:

| `system_code` | `covered_entities` | `coverage_pct` | Пояснение |
|---|---|---|---|
| `SYS-ARIS` | 1186 | 100.0 | Все 8 строк `LPM-001` … `LPM-008` для BusinessProcess в состоянии `mapped` |
| `SYS-CATIA` | 39870 | 100.0 | Все 4 строки для полей снимка CATIA в состоянии `mapped` |
| `SYS-ERP` | 0 | 12.3 | 910 из 7340 колонок ERP имеют правило; остальные `unmapped` |

У ERP `covered_entities` = 0: поток ERP → Semantic Layer передаёт только описания колонок, а не сами
элементы справочников, поэтому активов ERP в каталоге нет, и покрытие ERP видно только через
`coverage_pct`. Значение 12.3 получено округлением вниз: 910 / 7340 × 100 = 12.397…
