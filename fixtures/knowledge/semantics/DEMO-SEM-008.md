# Справочники и нормализация названий

> Синтетический демо-документ: описывает вымышленную учебную модель, не системы банка.

## Назначение

Документ описывает справочники, на которые ссылаются логические модели и датасеты, и правила нормализации
названий процессов и объектов. Цель — согласованность (consistency): одно и то же значение должно
выглядеть одинаково во всех источниках, а сравнение названий должно давать один и тот же результат при
любом порядке загрузки.

## Определение

Справочник — управляемый список значений с кодом и названием. Эталонные копии всех справочников ведутся в
MDM (`SYS-MDM`, Master Data Management); семантический слой получает их копию только для чтения и сам
справочники не меняет. Нормализация — детерминированное преобразование названия: «отображаемое название»
приводится к единому виду, а для сравнения дополнительно строится ключ `name_key`.

Справочники семантического слоя:

| Справочник | Содержимое | Пример |
|---|---|---|
| `DICT_OWNER_ROLE` | Роли-владельцы, код `ROLE-` и 3 цифры | `ROLE-014` — `process-owner-requests-demo` |
| `DICT_SYSTEM_CODE` | Коды систем | `SYS-ARIS`, `SYS-CATIA`, `SYS-CRM`, `SYS-ERP`, `SYS-MDM`, `SYS-CAT`, `SYS-EVH`, `SYS-EXTREG`, `SYS-ARC`, `SYS-DQM` |
| `DICT_LIFECYCLE_STATE` | Состояния процесса и их физические коды | `active` / `A`, `draft` / `D` |
| `DICT_DEPENDENCY_TYPE` | Типы зависимостей графа | `assembly`; `reference` зарезервирован и не заполняется |
| `DICT_NAME_SYNONYM` | Сокращения и синонимы названий | «Согл.» → «Согласование» |

## Атрибуты

Элемент любого справочника:

| Атрибут | Тип | Обязательный | Описание | Источник |
|---|---|---|---|---|
| `dict_code` | string | да | Код справочника, например `DICT_OWNER_ROLE` | MDM |
| `item_code` | string | да | Код элемента, уникален внутри справочника, не переиспользуется | MDM |
| `item_name` | string | да | Значение элемента в том виде, в каком его используют источники и каталог | MDM |
| `item_name_key` | string | да | Ключ сравнения названия | Вычисляется по правилу 7 |
| `is_active` | boolean | да | `false` — элемент выведен, но хранится для истории | MDM |
| `valid_from` | date | да | Дата начала действия элемента | MDM |

## Связи с другими сущностями

- `owner_role` в BusinessProcess и в датасете Process Overview — значение `item_name` из `DICT_OWNER_ROLE`;
  в физической таблице хранится `item_code`.
- `source_system` во всех моделях — код из `DICT_SYSTEM_CODE`.
- `name_key` используется правилами разрешения неоднозначных сущностей (DEMO-SEM-012) для поиска омонимов.
- Справочники, первичным источником которых является CRM, попадают в MDM через поток CRM → MDM; изменения
  доходят с задержкой до 15 мин.

## Ограничения

Правила нормализации названий (применяются по порядку):

1. Пробелы по краям удаляются, последовательности пробелов внутри сжимаются до одного.
2. Кавычки приводятся к «ёлочкам».
3. Сокращения раскрываются по `DICT_NAME_SYNONYM` («Согл. заявки» → «Согласование заявки»).
4. Технические суффиксы « (копия)» и « (copy)» удаляются.
5. Первая буква делается заглавной, остальной регистр сохраняется; буква «ё» в отображаемом названии
   сохраняется.
6. Название длиннее 255 символов после нормализации не обрезается: запись уходит стюарду данных в очередь
   `q_name_review`.
7. Ключ сравнения `name_key`: нижний регистр, «ё» → «е», знаки препинания удаляются, пробелы сжимаются.

Общие ограничения:

- Нормализация идемпотентна: повторное применение к результату ничего не меняет.
- Нормализация никогда не меняет идентичность: Process ID и `object_id` от названия не зависят.
- Коды элементов (`item_code`) не переиспользуются; выведенный элемент получает `is_active = false`.
- Сопоставление «похожих» названий без записи в `DICT_NAME_SYNONYM` запрещено: нечёткое сравнение не
  применяется.

## Пример

Исходное название из ARIS: `  Согл.  заявки "срочной" (копия)`.

| Шаг | Результат |
|---|---|
| 1 | `Согл. заявки "срочной" (копия)` |
| 2 | `Согл. заявки «срочной» (копия)` |
| 3 | `Согласование заявки «срочной» (копия)` |
| 4 | `Согласование заявки «срочной»` |
| 7 (ключ) | `согласование заявки срочной` |

`process_name` = «Согласование заявки «срочной»», `name_key` = `согласование заявки срочной`.
