# External Registry: внешний справочник

> Синтетический демо-документ: описывает вымышленную учебную модель, не системы банка.

**Статус: черновик (draft).** Всё ниже — предложение для обсуждения. Ни состав полей, ни расписание, ни ответственный со стороны поставщика не утверждены, и опираться на этот профиль как на авторитетный нельзя.

## Назначение

`SYS-EXTREG` — условный внешний справочник: вымышленный отраслевой классификатор `EXT-IND`, который ведёт сторонняя организация учебного сценария. Предлагается загружать его в MDM как новый справочник, чтобы датасеты могли группировать объекты по отрасли одинаково, без локальных вариантов написания.

## Границы (Scope)

Предлагаемые границы: коды классификатора, их названия, иерархия и период действия. Вне границ: сведения о конкретных организациях, рейтинги и любые данные, которые поставщик передаёт по отдельным договорам. Справочные значения, уже закреплённые за MDM, этот профиль не дублирует. Ожидаемый объём — около 1 200 кодов в четырёх уровнях иерархии.

## Сущности и идентификаторы

Предлагаемые поля элемента классификатора:

| Поле | Смысл |
|---|---|
| `ext_code` | код, формат `EXT-IND-` + 4 цифры, например `EXT-IND-0420` |
| `ext_name` | название раздела |
| `ext_parent_code` | код родителя; у корневых разделов пусто |
| `ext_level` | уровень иерархии от 1 до 4 |
| `ext_valid_from` | дата начала действия кода |
| `ext_release` | номер выпуска классификатора, например `2026.2` |

## Выгружаемые метаданные (Outputs)

Предложение: поставщик раз в неделю, по понедельникам, передаёт полный файл выпуска в согласованный каталог обмена. Загрузка сравнивает `ext_release` с последним принятым выпуском и при совпадении ничего не делает. Получатель — MDM: классификатор становится справочником `DICT_INDUSTRY` (рабочее название), его элементы получают `item_code` из `ext_code`. Событий в Event Hub внешний справочник сам не публикует.

## Ограничения

- Профиль — черновик: факты не утверждены, датасеты и потоки на них не опираются.
- Получение файлов по произвольным внешним адресам не допускается: файл передаёт владелец в заранее согласованное место.
- Условная лицензия поставщика запрещает распространять классификатор за пределы учебной среды.
- Порядок обработки кодов, исключённых из нового выпуска, не определён.
- SLA, частота обновления у поставщика и срок поддержки выпусков неизвестны — на такие вопросы ответ «нет данных».

## Владельцы и роли

- **Owner** (владелец): предварительно `src-owner-extreg` в команде `demo-source-owners`; ответственный со стороны поставщика не определён.
- **Steward** (стюард): не назначен; предлагается стюард MDM.
- **Reviewer** (ревьюер): не назначен.

Открытые вопросы для ревью: кто отвечает со стороны поставщика; нужна ли еженедельная частота; как обрабатывать исключённые коды; кто проверяет лицензионные условия. Новая заявка на источник не нужна: владелец дорабатывает этот черновик, и до его утверждения интеграцию External Registry → MDM нельзя описывать как утверждённую.

## Пример

Раздел `EXT-IND-0420` «Оптовая торговля (демо)», родитель `EXT-IND-0400`, уровень 2, выпуск `2026.2`. Если подключение утвердят, в MDM появится элемент справочника `DICT_INDUSTRY` с `item_code = EXT-IND-0420`. Пока профиль в статусе draft, такой элемент не создаётся, а вопрос «какой отраслевой код у объекта» не имеет ответа в демо-базе.
