# Обзор условного ландшафта источников

> Синтетический демо-документ: описывает вымышленную учебную модель, не системы банка.

## Назначение

Документ — единая точка входа в профили условных систем-источников, из которых семантический слой демо-модели получает метаданные. Для каждой системы указаны код `SYS-*`, назначение, основные сущности и режим обмена. Подробности живут в отдельных профилях: обзор их не заменяет, и при расхождении прав профиль конкретной системы.

## Границы (Scope)

В обзор входят десять систем:

- четыре первоисточника бизнес-сущностей — ARIS, CATIA, CRM, ERP;
- система мастер-данных MDM;
- каталог метаданных Data Catalog;
- транспорт событий Event Hub;
- внешний справочник External Registry (профиль — черновик);
- архив исторических снимков Archive Store (профиль на ревью);
- монитор качества Data Quality Monitor.

Не входят: потребители датасетов, Consumer API и само демо-приложение Semantic Knowledge Hub. Правила владения и границ ответственности вынесены в отдельный документ [[DEMO-SRC-012]].

## Сущности и идентификаторы

| Код | Система | Назначение | Основные сущности | Режим обмена |
|---|---|---|---|---|
| `SYS-ARIS` | ARIS | процессные модели | процесс (`aris_object_guid`) | инкремент каждые 6 ч, пакеты по 500 записей |
| `SYS-CATIA` | CATIA | метаданные изделий и сборок | изделие (`catia_part_number`), сборка (`assembly_ref`) | суточная дельта, ежедневно в 02:30 |
| `SYS-CRM` | CRM | справочные карточки и их идентификаторы | справочная карточка (`crm_card_id`) | CDC через Event Hub, задержка до 15 мин |
| `SYS-ERP` | ERP | справочники и описания таблиц транзакций | позиция справочника (`erp_ref_code`), колонка (`erp_table` + `erp_column`) | ночной full refresh в 01:00, пакеты по 2 000 строк |
| `SYS-MDM` | MDM | мастер-данные, эталонные справочники | мастер-запись (`mdm_golden_id`) | читает CDC из CRM, публикует изменения в Event Hub |
| `SYS-CAT` | Data Catalog | описание и поиск активов | актив (`catalog_asset_id`), процесс (`process_id`) | принимает потоки ARIS и CATIA, отдаёт активы датасетам |
| `SYS-EVH` | Event Hub | уведомления об изменениях | событие (`event_id`) | топик `demo.metadata.changes.v1` |
| `SYS-EXTREG` | External Registry | внешний справочник | код классификатора (`ext_code`) | предложен еженедельный файл, не утверждён |
| `SYS-ARC` | Archive Store | исторические снимки | снимок (`snapshot_id`) | ежемесячный снимок, только чтение |
| `SYS-DQM` | Data Quality Monitor | контроль качества | результат проверки (`check_id`) | проверки после каждой загрузки |

Коды `SYS-*` — единственные допустимые значения полей `source_system` и `system_code` в событиях, датасетах и отчётах качества. Код пишется заглавными буквами и не меняется при переименовании системы.

## Выгружаемые метаданные (Outputs)

Сам обзор ничего не выгружает. Он фиксирует роль каждой системы в ландшафте:

- **первоисточник** (system of record): ARIS — процессы, CATIA — изделия и сборки, CRM — справочные карточки, ERP — позиции справочников и описания колонок, MDM — только мастер-записи справочников;
- **производная система**: Data Catalog собирает описания из первоисточников, Archive Store хранит их копии на дату и архивные снимки документов;
- **транспорт**: Event Hub доставляет уведомления, но не владеет данными;
- **измеритель**: Data Quality Monitor считает метрики и не исправляет записи.

Эта классификация нужна, чтобы отвечать на вопрос «где исправлять ошибку»: исправление всегда вносится в первоисточник.

## Ограничения

- Для демо-потоков SLA не определён; все расписания условные.
- Профиль External Registry — черновик (draft), его факты не авторитетны.
- Профиль Archive Store на ревью и пока без владельца (`unassigned`).
- Объёмы в профилях приблизительны и нужны только для учебных примеров.

## Владельцы и роли

Обзор ведёт команда `demo-source-owners`. У каждой системы есть роль владельца вида `src-owner-<система>` и роль стюарда вида `src-steward-<система>` (например, `src-owner-aris`, `src-steward-crm`). Правила назначения ролей и проверки профилей описаны в DEMO-SRC-012.

## Пример

Вопрос: «откуда берётся `process_name` в карточке каталога и когда он обновится?» По таблице: поле живёт в `SYS-CAT`, но первоисточник — `SYS-ARIS` (поле `aris_object_name`), обмен — инкремент каждые 6 ч. Значит, исправление вносится в ARIS и появится в каталоге после ближайшего инкремента. Детали — в профиле ARIS (DEMO-SRC-002).
