# Качество метаданных: полнота (completeness) (демо)

> Синтетический демо-документ: описывает вымышленную учебную модель, не системы банка.

## Назначение

Регламент задаёт измеримое правило полноты (completeness) метаданных: какая доля записей должна иметь
заполненные обязательные атрибуты, чтобы пакет загрузки или датасет считался пригодным. Порог полноты по
умолчанию — 95 %; датасет Process Overview устанавливает для своей области более строгий порог 98 %, и
внутри этой области действует именно он.

## Область применения

Пакеты загрузки метаданных из источников в каталог (`SYS-CAT`) и датасеты семантического слоя.
Обязательные атрибуты задаются контрактом источника или спецификацией датасета. Для ARIS обязательны
`aris_object_guid`, `aris_object_name`, `aris_owner_role`; эти атрибуты проверяет [[DEMO-INT-003]].

## Правила

1. Порог по умолчанию — **95 %** записей пакета или датасета, у которых заполнены все обязательные
   атрибуты.
2. Атрибут считается заполненным, если значение не `null`, не пустая строка и не состоит из одних
   пробелов. Заглушки `N/A`, `-` и `unknown` считаются незаполненными.
3. Доля сравнивается с порогом без округления вверх: 94,96 % — это меньше 95 %, а не «примерно 95 %».
4. Область (scope) может установить более строгий порог. Датасет Process Overview (DEMO-SEM-009)
   требует **98 %** строк с заполненными `process_id`, `process_name`, `owner_role`. Внутри своей
   области действует более строгое правило, вне её — порог по умолчанию.
5. Различие порогов 95 % и 98 % — это различие области действия, а не противоречие между документами.
6. Порог мягче 95 % область установить не может без отдельного исключения, согласованного Owner этого
   регламента.
7. Показатель записи `completeness_score` — процент заполненных атрибутов одной записи:
   `completeness_score = заполненные атрибуты записи / число учитываемых атрибутов × 100`, один знак
   после запятой. Набор учитываемых атрибутов задаёт спецификация датасета; в Process Overview это шесть
   атрибутов BusinessProcess, и запись без одного `process_path` получает 83.3.
8. `completeness_score` описывает отдельную запись и не заменяет порог пакета: решение о приёме пакета
   или публикации датасета принимается по доле записей из правил 1 и 4.
9. Если порог не достигнут, пакет целиком не принимается; для ARIS он уходит в карантин
   `q_aris_rejected` (DEMO-INT-003). Необязательные атрибуты в расчёт порога не входят.

## Исключения

- Временное исключение для новой области оформляется отдельным документом со сроком действия не более
  90 дней и согласием Owner этого регламента.
- Пустой пакет (0 записей) по полноте не оценивается и фиксируется как событие «нет данных».

## Контроль и проверка

- Data Quality Monitor (`SYS-DQM`) после каждой загрузки публикует метрику `dq_completeness` — долю
  записей с заполненными обязательными атрибутами — с результатом `pass`, `warn` или `fail`.
- Идентификатор проверки строится по формату монитора `DQ-<правило>-<объект>`; для Process Overview это
  `DQ-COMPL-SEM009`.
- Результат `fail` — сигнал для Steward и задача для Owner источника или датасета; монитор данные не
  исправляет.
- Process Overview публикует `completeness_score` каждой записи, чтобы потребитель видел полноту без
  обращения к монитору.

## Пример

Пакет ARIS: 500 записей, у 480 заполнены все три обязательных атрибута — 96,0 %. Это не ниже 95 %,
пакет проходит порог по умолчанию.

Process Overview получает 1 000 строк. `owner_role` заполнен в 975 из них — 97,5 %. Общий порог 95 %
выполнен, но правило области 98 % нет, поэтому проверка `DQ-COMPL-SEM009` даёт `fail`. Ответ на вопрос
«какой порог полноты верен» звучит так: оба, каждый в своей области.
