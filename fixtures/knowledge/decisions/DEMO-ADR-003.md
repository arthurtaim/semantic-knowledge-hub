# Решение о детерминированных source ID

> Синтетический демо-документ: описывает вымышленную учебную модель, не системы банка.

Запись архитектурного решения (ADR, Architecture Decision Record) о том, как формируются идентификаторы
источников для цитат, связей графа и журнала аудита.

## Контекст

Каждый результат поиска и каждый ответ ассистента обязан нести provenance: из какого источника (`local`,
`gitlab`, `confluence`) и из какой ревизии взят фрагмент (DEMO-GOV-011). Цитаты сохраняются в журнале аудита,
рёбра графа ссылаются на документы, кэш фрагментов Confluence хранит выдержки. Если идентификатор источника
меняется при переименовании файла или переиндексации, ломаются сразу три вещи: старые цитаты ведут в пустоту,
рёбра графа становятся «висячими», а повторная синхронизация видит «новый» документ и создаёт дубликат.

Первая версия демо строила ключ из заголовка. Это быстро дало сбои: заголовки «обзор потока» есть и у ARIS, и у
CATIA; стрелка «→» и кавычки по-разному нормализуются; перевод заголовка на английский менял ключ.

## Решение

1. **Source ID детерминирован**: вычисляется только из стабильных атрибутов источника и при одинаковых входных
   данных всегда одинаков. Случайные UUID при индексации и порядковые номера в выдаче не используются.
2. **Пространство имён обязательно** — формат `<namespace>:<стабильный ключ>`:
   - локальный каталог: `local:<id документа>`, например `local:DEMO-INT-002`;
   - репозиторий знаний GitLab: `gitlab:<project>:<id документа>`, например `gitlab:demo-kb:DEMO-INT-002`;
   - Confluence: `confluence:<instance>:<page-id>:<version>`, например `confluence:demo-wiki:100234:7`.
3. **Ключ — это `id` из frontmatter, а не путь и не заголовок.** Переименование или перемещение файла не меняет
   `id`, значит, не меняет и source ID. Валидатор отклоняет правку, которая меняет `id` существующего документа
   (ошибка `id_changed`), а два документа с одним `id` считаются ошибкой `duplicate_id`.
4. **Ревизия хранится отдельно.** Для `local` и `gitlab` ревизия содержимого (hash или commit, [[DEMO-GOV-009]])
   не входит в source ID: цитата = source ID + ревизия. Для Confluence номер версии страницы входит в ключ,
   потому что у страниц нет frontmatter-`id`, а версия — единственная устойчивая ссылка на процитированный текст.
5. **Сравнение `id` без учёта регистра**, хранение — в исходном написании.
6. Один и тот же `id` в разных пространствах имён — это разные источники: `local:DEMO-INT-002` и
   `gitlab:demo-kb:DEMO-INT-002` автоматически не склеиваются.

## Рассмотренные альтернативы

- **Заголовок как ключ.** Отклонено: заголовки меняются, повторяются и по-разному транслитерируются.
- **Путь к файлу как ключ.** Отклонено: перемещение документа между папками ломает все цитаты и рёбра.
- **UUID, выдаваемый при индексации.** Отклонено: переиндексация с нуля выдаёт новые значения, результат
  невоспроизводим, а старые цитаты теряются.
- **Hash содержимого как ключ.** Отклонено: любая правка опечатки создаёт «новый» документ; hash уместен как
  ревизия, а не как идентичность.

## Последствия

- Переименование файла без смены `id` даёт ровно один результат поиска и рабочую ссылку из старых цитат.
- Принцип совпадает с ключом идемпотентности интеграций (DEMO-INT-012): там ключ строится из
  `source_system + source_object_id + source_changed_at`, то есть тоже из стабильного идентификатора объекта,
  а не из его названия.
- Журнал аудита хранит пару «source ID + ревизия», поэтому можно точно восстановить, на какой текст опирался
  ответ.
- Авторы обязаны не менять `id`; для смены смысла документа создаётся новый документ, а старый переводится в
  `deprecated` с ребром `supersedes` от преемника.

## Статус решения

Принято (accepted), версия 1.0. Решение распространяется на все адаптеры источников; новый адаптер обязан
объявить своё пространство имён до подключения.
