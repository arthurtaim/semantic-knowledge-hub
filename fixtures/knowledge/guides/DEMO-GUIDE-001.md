# Как найти описание источника

> Синтетический демо-документ: описывает вымышленную учебную модель, не системы банка.

## Когда использовать

Руководство нужно, когда вы встретили в маппинге, датасете или ошибке интеграции название или код системы и
хотите открыть её профиль: какие сущности она отдаёт, какие поля выгружает, кто владелец и какие у неё
ограничения. Профили источников лежат в папке `sources/`, имеют тип `source` и владельца `demo-source-owners`.

## Пошагово

**Способ 1. По коду системы.** У каждой условной системы есть код вида `SYS-…`:

| Система | Код |
|---|---|
| ARIS | `SYS-ARIS` |
| CATIA | `SYS-CATIA` |
| CRM | `SYS-CRM` |
| ERP | `SYS-ERP` |
| MDM | `SYS-MDM` |
| Data Catalog | `SYS-CAT` |
| Event Hub | `SYS-EVH` |
| External Registry | `SYS-EXTREG` |
| Archive Store | `SYS-ARC` |
| Data Quality Monitor | `SYS-DQM` |

1. Введите код в строку поиска целиком, например `SYS-ARIS`.
2. Среди результатов выберите документ типа `source`: для ARIS это DEMO-SRC-002.
3. Если код встретился в поле `source_system` датасета или в `system_code` отчёта покрытия, ищите тот же код —
   он одинаков во всех документах.

**Способ 2. Через фильтры каталога.**

1. Откройте каталог документов и задайте фильтр `type = source`.
2. Добавьте `status = approved`, чтобы оставить только авторитетные профили.
3. При необходимости уточните владельца `owner = demo-source-owners` или тег (например, `aris`).

**Способ 3. По графу связей.**

1. Откройте обзор ландшафта DEMO-SRC-001.
2. Перейдите по исходящим рёбрам `describes`: они ведут на профили DEMO-SRC-002…DEMO-SRC-011.
3. Чтобы понять, кто отвечает за источник и где проходят его границы, перейдите в DEMO-SRC-012.

Найденный профиль построен по шаблону Source System Profile (описание шаблона — DEMO-PROC-008), поэтому
нужный раздел легко найти по заголовку: Назначение, Границы (Scope), Сущности и идентификаторы, Выгружаемые
метаданные (Outputs), Ограничения, Владельцы и роли, Пример.

## Пример

Задача: в датасете Process Overview у записи `PRC-000417` указано `source_system = SYS-ARIS`; нужно понять,
откуда берётся поле `owner_role`.

1. Поиск по `SYS-ARIS` выдаёт DEMO-SRC-002 «ARIS: условная модель процессных метаданных».
2. В разделе «Выгружаемые метаданные» видно поле `aris_owner_role` — из него при маппинге получается
   `owner_role`.
3. В метаданных профиля указан владелец `demo-source-owners`; где проходят границы ответственности за
   источник, объясняет DEMO-SRC-012.

Тот же профиль находится вторым способом (фильтр `type = source` + тег `aris`) и третьим (ребро `describes`
из DEMO-SRC-001).

## Частые ошибки

- **Путают `SYS-CAT` и `SYS-CATIA`.** `SYS-CAT` — Data Catalog, `SYS-CATIA` — CATIA. Поиск по префиксу
  `SYS-CAT` найдёт обе системы; проверяйте код целиком.
- **Принимают черновик за профиль.** DEMO-SRC-009 (External Registry) пока в статусе `draft` — это не
  утверждённое описание, на него нельзя ссылаться как на факт.
- **Не замечают статус ревью.** DEMO-SRC-010 (Archive Store) находится в `in_review` и без назначенного
  владельца (`unassigned`); вопросы по нему адресуйте через DEMO-SRC-012, а не автору черновика.
- **Ищут по смыслу аббревиатуры.** «MDM» в текстах ARIS иногда означает «модель метаданных», а не Master Data
  Management; профиль мастер-данных ищите по коду `SYS-MDM`.
- **Ищут интеграцию вместо источника.** Документы `DEMO-INT-…` описывают потоки между системами; сам профиль
  системы — всегда документ типа `source`.

## Связанные документы

- **DEMO-SRC-001** — обзор ландшафта источников; отправная точка способа 3 (рёбра `describes`).
- **DEMO-SRC-012** — владение и границы источников; куда идти, когда нужно понять, кто отвечает за систему.
- **DEMO-SRC-002** — профиль ARIS, на котором построен пример.
- **DEMO-PROC-008** — описание шаблона Source System Profile, объясняющее структуру разделов любого профиля.
- **DEMO-SRC-009** — профиль External Registry в статусе черновика; пример из раздела «Частые ошибки».
- **DEMO-SRC-010** — профиль Archive Store на ревью и без владельца; второй пример из раздела «Частые ошибки».
