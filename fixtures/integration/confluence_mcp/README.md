# Сценарии воспроизведения Confluence MCP

Каждый `*.json` — записанный «диалог» с MCP-сервером: какие инструменты он объявляет (`tools_pages`, по страницам `nextCursor`), что отвечает на `tools/call` (`calls`, первый подходящий по `match`) и что должен сделать коннектор (`expect`). Тест `backend/tests/integration/test_confluence_mcp_replay.py` прогоняет все файлы без сети.

## Как добавить сценарий после подключения тестового сервера
1. На **тестовом** пространстве Confluence создайте страницы только с синтетическим текстом (префикс `[TEST]`).
2. Запишите ответы `tools/list` и `tools/call` утверждённого MCP-сервера (например, через MCP Inspector внутри контура).
3. Обезличьте: замените реальные хосты на `*.test.example`, удалите токены, имена людей, ID внутренних систем. **Корпоративный контент в репозиторий не попадает.**
4. Укажите в `config` то же сопоставление инструментов и полей, что будет в `CONFLUENCE_MCP_TOOL_MAP` / `CONFLUENCE_MCP_RESULT_MAP`, и опишите ожидания в `expect`.
5. `make test-backend` — сценарий должен пройти; если нет, поправьте сопоставление в конфигурации, а не код.
