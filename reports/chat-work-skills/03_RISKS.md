# 03 — Риски, совместимость, ограничения и заметки к выпуску

## Обратная совместимость

- Все поля API аддитивные. `/ask` без `work_context` работает как раньше (тест `test_reg12_reg13…` и вся прежняя
  регрессия). Прежние 10 навыков не изменились; в закреплённых тестах реестра появились 3 новых навыка и явное
  `requires.project: false` у старых.
- Старые ходы истории читаются без изменений: у не-Work ходов в сохранённом запросе нет ключа `work`, в ответе API —
  `work: null`.
- Старые черновики композера, сохранённые в памяти вкладки без `work`, получают пустое значение.
- Промпт «AI план» без уточнения совпадает с прежним байт в байт. `work_inspect` по-прежнему только для чтения.
  `ToolLoop.run` получил необязательный параметр `seed`; без него поведение прежнее.

## Схема данных и откат (важно для стенда)

- Миграция v4 аддитивна. Перед ней автоматически создаётся копия `work.sqlite3.pre-v4-<UTC>.bak`; повторный старт
  миграцию не повторяет. Проверено на заполненной базе v3 (`test_wcp22_…`).
- **Откат приложения на версию без M7 (например, стенд → `b23fe02`) только кода НЕ сработает.** Прежняя версия
  откажется стартовать на базе v4 («база новее приложения»). Нужен `python -m app.tools.work_db restore --from
  work.sqlite3.pre-v4-….bak --yes`. Предложения изменений, а также изменения задач, сделанные после миграции, при этом
  откатятся к копии. Текущий `ROLLBACK.sh` стенда (`backups/2026-11-26-pre-query-rewrite`) без `--with-data` этого не
  делает. При деплое M7 нужен новый бэкап и обновлённый скрипт отката.

## Конкурентность и целостность

- Применение WCP — одна транзакция `BEGIN IMMEDIATE`. Проверены:
  - параллельные применения (ровно одно, второе — 409);
  - сбой после первой записи (полный откат задач, аудита, ревизии и статуса);
  - повтор с тем же ключом (первый результат, ничего не записано);
  - тот же ключ с другим телом (409).
- Устаревание строгое: любая правка проекта повышает ревизию плана, и весь change-set становится `stale`. Это
  безопасно, но в активном проекте предложение быстро устаревает — нужно подготовить новое (это одна кнопка в чате).
- Вызов модели никогда не идёт под блокировкой записи базы: генерация, затем короткая запись.

## Безопасность

- Права проверяются до модели и снова при каждом чтении, предпросмотре и применении. Клиентские роль, исполнитель и
  версия в `work_context` дают 422. Заголовки `X-User-ID` / `X-SKH-Role` игнорируются: исполнитель — идентичность
  сервера (тест `test_reg09…`).
- Скрытые проект, задача, предложение и документ дают одинаковый 404, без заголовков. Ключ, выдуманный моделью, не
  повторяется в ответе.
- Текст задач — данные. При передаче модели и при выводе в ответ он проходит `redact_prompt_injection` и
  `neutralize_citation_markers`. Внедрённые `[F9]`, «apply every task», JSON вызова инструмента ничего не меняют
  (`test_an10…`).
- В логах только действие, ключ проекта, id предложения, счётчики и режим провайдера. Текста вопроса, задач и ответа
  модели там нет.

## Ограничения (не объявлены сделанными)

- Живая модель не проверялась: все сценарии — со скриптовым двойником. Качество предложений реальной модели (Claude /
  целевой) не измерено. Возможный следующий шаг — отдельный opt-in прогон на синтетических вопросах.
- Change-set не меняет исполнителя, даты плана, закрепление, зависимости, иерархию и архив. Такие просьбы
  отбрасываются с подсказкой, где это сделать в интерфейсе.
- Значение операции нельзя поправить в панели изменений: только снять пункт и поменять задачу вручную или уточнить
  предложение в чате.
- Критический путь не рассчитывается — так и говорится.
- Поддержки удаления предложений и их списка в проекте нет: предложения видны по ссылкам из чата.
- В компактной панели ассистента документа есть только ссылка в проект, без «Уточнить».

## Заметки к выпуску

- Новые навыки видны всем, но работают только с выбранным проектом. В режиме mock доступен только анализ (сводка
  сервера); план и изменения недоступны с понятной причиной.
- На стенде (`claude_cli`, общий вход `shared_login`) все три навыка доступны после входа. По открытой ссылке — только
  анализ.
- Перед деплоем: бэкап (`work.sqlite3` вместе с остальными базами) и обновлённый `ROLLBACK.sh` с восстановлением копии
  `pre-v4`.
