# 04 — Отложено и почему

Демо намеренно работает так: один оператор с полными правами, только синтетические данные. Поэтому пункты
безопасности корпоративного развёртывания не блокируют выпуск демо и в этой ветке не менялись.

## 1. DEFERRED_BY_OWNER_DEMO_SCOPE — код не менялся

| audit_id | Суть | Почему отложено | Влияние на демо | Рекомендация на будущее (корпоративный контур) |
|---|---|---|---|---|
| CODE-001 / SYS-004 (P1) | за публичным шлюзом режим «только просмотр» действует лишь в «Работе»; шаблоны, черновики, синхронизация и AI доступны на запись | глобальный read-only и права демо-оператора исключены владельцем | стенд за логином (`Caddyfile.login`): писать может только тот, кто знает общий пароль, — это решение владельца | перед любым общим развёртыванием — SSO/RBAC вместо `LocalDemoPolicy`; при `WORK_PUBLIC_EXPOSURE` политика «только чтение» для всех маршрутов; по умолчанию `Caddyfile.login` |
| CODE-006 (P2) | Basic Auth на IP по простому HTTP; `shared_login` без маркера доверяет шлюзу; пароль в argv при генерации | Caddy, HTTP/HTTPS и механизм входа исключены | общий пароль может перехватить сеть при входе по IP; по ссылке sslip.io он шифруется | перенаправление HTTP → HTTPS или только HTTPS-хост; маркер `public-login` обязателен для записи; пароль через stdin |
| CODE-007 (P3) | `capabilities.can_write`/`can_view_audit` не зависят от роли | проявляется только в командном режиме membership (`team_ready=false`, в демо не используется); это многопользовательский RBAC | нет: в режимах `local_operator`, `shared_login`, `read_only` флаги верны | вычислять флаги по ролям участника; во вкладке истории задачи учитывать роль в проекте |
| CODE-009 (P3) | клиентский `X-Request-ID` становится `correlation_id` аудита | защита целостности аудита от подделки клиентом — это security hardening | за nginx значение перезаписывается; в Vite dev — нет | генерировать собственный id, клиентский хранить отдельно |
| CODE-016 (P3) | файлы SQLite создаются с правами 0644 | права файлов из соображений безопасности исключены | в контейнере один пользователь | `umask`/`chmod 0600` для баз |
| CODE-017 (P3) | нет ограничения частоты запросов к маршрутам с моделью | rate limiting исключён | на стенде с общим входом расходуется подписка; один AI-запрос за раз (`CLAUDE_WORKER_MAX_CONCURRENCY=1`) | квоты на пользователя или маршрут |
| SYS-008 (P3) | внешние ссылки из ответа модели кликабельны без пометки | защита от фишинга и инъекций — security hardening | данные синтетические, ассистент не цитирует такие ссылки как источники | показывать внешние ссылки модели текстом или с пометкой «непроверено», либо по allowlist |
