# 01 — Архитектура: точка решения, контракт слабой модели, fallback

Полное описание — `docs/ADAPTIVE_RAG.md`, решение — ADR-044 в `docs/DECISIONS.md`.

## 1. Где принимается решение

Одно место: `AssistantService._prepare_events` (`backend/app/services/assistant.py`). Через него проходят `/ask`,
`/ask/stream`, tool loop M5.7 и навыки на основе ask, поэтому решение, вызовы MCP и источники у них одинаковые.

```text
локальный поиск (без изменений)
  → scope: team → Confluence и ворота не вызываются
           corporate → поиск в Confluence без локального решения (external_scope_selected)
           search_external → принудительный поиск (explicit_request)
           team+corporate → EvidenceGate.decide (app/services/evidence_gate.py)
               нет локальных фрагментов → 1 поиск чистым запросом из слов вопроса, без модели (no_local_passages)
               провайдер без capability / EXTERNAL_GATE=lexical → LOCAL_SUFFICIENCY v2, как раньше
               иначе ≤ 5 карточек E1… → 1 вызов модели (+ ≤ 1 repair, если ответ не JSON)
                 → строгий разбор → проверки сервера → sufficient | need_external (≤ 2 запроса) | uncertain (1 проба)
                 | invalid → резервное правило v2, видимо в трассе
  → ExternalEvidenceService.retrieve(queries=…, focus=…) — общие лимиты (≤ 10 кандидатов, ≤ 3 fetch, ≤ 6 фрагментов,
    ≤ 16 000 символов, один дедлайн 12 с), outcome
  → ответ: пробел передаётся модели ответа как данные; серверная проверка цитат без изменений
```

Tool loop получает уже готовые фрагменты (локальные и внешние) и описание пробела. Инструмента Confluence в цикле нет,
поэтому повторного или конкурирующего внешнего поиска быть не может (проверено тестом
`test_tool_mode_uses_the_one_gate_decision_and_never_searches_twice` для `internal_api` и `claude_cli`).

## 2. Контракт модели

Обычный chat completion: system (~1 200 символов, без длинной runtime-политики) + user (вопрос ≤ 1 000 символов,
предыдущий вопрос ≤ 300 как контекст, серверный факт «слова вопроса, которых нет ни в одном документе SKH», ≤ 5
карточек с JSON-метаданными). Средний размер всего запроса в замерах — 4 400–5 200 символов (≈ 1,1–1,7 тыс. токенов по
оценке «3–4 символа на токен»; токенизатор целевой модели неизвестен).

Ответ — один JSON: `decision` (3 состояния), `known` ≤ 3, `missing` ≤ 3, `evidence_ids` ≤ 5, `search_queries` ≤ 2.
Pydantic `extra=forbid`, строгие типы, лимиты длины. Нет confidence-чисел, нет chain-of-thought, нет tool calls.

| Ответ модели | Что делает сервер |
|---|---|
| JSON в ```json-ограде, текст вокруг, `null` вместо `[]`, дубли запросов | принимает (факты не меняются) |
| проза, «да/нет», строка, массив | один repair-запрос с короткой пометкой сервера; повтор — `invalid` |
| лишний ключ, неизвестный decision, неверный тип, превышение лимитов, E7, `need_external` без `missing`/запроса, `sufficient` без evidence или с `missing` | `invalid` без repair |
| `sufficient`, но в цитируемых фрагментах нет ID/аббревиатуры вопроса | не принимается → `uncertain`, одна проба |
| запрос с URL, хостом, IP, путём, `?key=` | запрос отклонён; если других нет — решение `invalid` (возможная инъекция) |
| запрос > 12 слов (вопрос целиком) | запрос заменяется чистым запросом сервера, решение и пробел остаются |
| запрос без ID вопроса | ID дописывается в начало |

## 3. Fallback

| Ситуация | Поведение |
|---|---|
| нет локальных фрагментов | 1 внешний поиск без вызова модели |
| invalid / timeout (`EXTERNAL_GATE_TIMEOUT_SECONDS`, 20 с) / ошибка провайдера | `EXTERNAL_GATE_INVALID_FALLBACK=lexical` (по умолчанию): решает правило v2; если оно не ищет — локальный ответ помечается неполным (предупреждение, confidence ≤ partial). `local`: всегда локально, неполный |
| лимит частоты (`EXTERNAL_GATE_RATE_LIMIT` за окно, на ACL-scope) | без модели и без поиска, видимое предупреждение |
| Confluence медленный/недоступен | существующие дедлайн, таймауты, circuit breaker → `outcome: source_unavailable` |
| Confluence ничего не подтвердил | «во внешнем источнике не удалось подтвердить … это не значит, что их там нет» |

Откат: `EXTERNAL_GATE=lexical` — прежнее поведение ветки `9b9f3c7` (проверено: knowledge-eval 210/216, без флипов).

## 4. Изменения сфокусированного внешнего поиска (только для запросов ворот)

- один MCP-поиск на запрос (≤ 2), результаты чередуются и дедуплицируются, ≤ 10 кандидатов всего;
- кандидат и фрагмент оцениваются по запросу, на который отвечают лучше всего (два аспекта — два запроса);
- раздел страницы считает заголовок страницы своим предметом, но сам должен содержать слово запроса (вступление,
  совпадающее только заголовком, не доказательство);
- фрагменты страницы упорядочены по тому, что каждый ДОБАВЛЯЕТ к предыдущим (вес слова — редкость среди фрагментов
  страницы), до 3 с одной страницы (всего ≤ 6, как раньше).

Поиск целым вопросом (`corporate`, `search_external`, лексическое правило, fallback) не изменён — это база для A/B.
ACL, проверки версии, кэш, дедупликация с утверждёнными документами и отзыв доступа не менялись.
