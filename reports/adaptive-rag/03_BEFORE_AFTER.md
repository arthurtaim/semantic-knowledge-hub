## 1. Выборка и протокол

- `fixtures/eval_adaptive/cases.yaml` — 40 новых вопросов (20 dev / 20 holdout): 7 local_single, 5 local_multi,
  5 paraphrase, 9 gap, 5 external_only, 4 nowhere, 2 restricted, 3 id_specific; 4 вопроса на английском.
- Написаны отдельным агентом **только по корпусу**: он не видел код ворот, gold-кейсы `fixtures/eval`, tuning-пробы и
  отчёты (три ранее раскрытых holdout-кейса старой задачи в выборку не входят). Каждый факт дословно есть в источнике
  (`gate_eval --validate`: 0 проблем).
- Метка `expected` — правда корпуса: «утверждённые документы команды отвечают полностью» или нет.
- **dev** использовался для разработки (диагностика → общие правки, коммит `9c909f2`, `313403c`). **holdout** запущен
  **один раз** после заморозки кода на `1fdc682`; после него код не менялся.
- Варианты: `main_lexical` (`f4ea26e`, LOCAL_SUFFICIENCY v1), `branch_lexical` (`9b9f3c7`, v2), `new_lexical` (эта
  ветка, mock без capability = v2), `new_oracle`, `new_weak`, `new_always_external`, `new_always_sufficient` — scripted-
  двойники (`app/evaluation/gap_doubles.py`, **не модели**). Старый код измерен тем же инструментом в отдельных
  worktree. `noise 120` — 120 «почти дубликатов» видимых страниц (обсуждения с теми же заголовками, без фактов).

Метрики: **accuracy** — внешний поиск вызван ⇔ ответ не полностью в документах команды; **given context** — то же
относительно того, что реально оказалось в контексте (если локальный поиск не принёс факт, для ворот это пробел, а не
их ошибка); **context_ok** — все факты в контексте модели ответа; **fact coverage** — доля фактов в контексте;
**ext page** — нужная страница Confluence в контексте.

## 4. Шумная вики (noise 120)

На этой выборке 120 почти-дубликатов не изменили ни одного решения, `context_ok`, `fact coverage` и `ext page` ни у
одного варианта; выросло только число загрузок страниц (dev: ветка 16 → 21 get, oracle 16 → 29; holdout: 17 → 21,
15 → 24). Различие «фокусный запрос против вопроса целиком» на шумном корпусе показано целевым тестом
`test_lf05_a_focused_query_finds_the_requirement_among_many_similar_pages`: правило v2 считает вопрос достаточным
(ложно), принудительный поиск целым вопросом заполняет все 3 загрузки похожими страницами, фокусный запрос находит
нужную страницу среди 120 похожих.

## 5. Разбор ошибок

**Ворота (oracle, относительно реального контекста):** dev — 0 ошибок; holdout — 2 (AG-002, AG-040). Оба вопроса на
английском: выдержка для карточки выбирается по словам вопроса, английские слова не совпадают с русским текстом, и
факт, который есть в контексте, не попадает в карточку. Диагноз прочитан после holdout-прогона, код не менялся
(`05_LIMITATIONS.md`).

**Локальный поиск (вне зоны ворот):** «достаточные» вопросы, чьи факты не попали в контекст, — dev AG-007, AG-009,
AG-011, AG-014; holdout AG-010, AG-015, AG-017, AG-038. Для любой политики это пробел; ворота законно ищут вовне.
Ранжирование retrieval по ТЗ не трогалось.

**Правило v2 (ветка) на holdout:** 4 ошибки при факте в контексте — AG-002, AG-008, AG-013 (лишний поиск:
`no_single_local_source` — факты в двух документах или другими словами), AG-040 (`low_term_coverage`); и пропуск
AG-035 (nowhere: слова вопроса нашлись, ответа нет — `local_sufficient`).

**Слабый двойник** (ошибки внедрены детерминированно, `PROFILE` в `gap_doubles.py`):
- dev: 4 invalid — 3 лишних ключа `confidence`, 1 выдуманный `E9`; 2 успешных repair после прозы вместо JSON;
  1 запрос «вопрос целиком» заменён чистым запросом сервера; 1 «sufficient» без ID вопроса в цитируемых фрагментах →
  `uncertain` и одна проба;
- holdout: 5 invalid — 3 лишних ключа `confidence`, 2 URL вместо запроса (`unsafe_query`); 1 repair; 4 запроса
  «вопрос целиком» заменены чистым запросом сервера.

Каждый invalid ушёл в резервное правило v2 (видно в `evidence_gate.fallback`); ни одна ошибка формата не дала ложное
«достаточно», невалидных цитат 0, утечек 0.

## 6. Стоимость и задержка

| | sufficient-кейсы | need_external-кейсы |
|---|---|---|
| вызовы модели ворот | 1 на вопрос с локальными фрагментами (weak: +1 repair в 1–2 из 20 вопросов) | 1 (+repair) |
| MCP (holdout, сумма) | ветка 7 search / 10 get → oracle 6 / 4 | ветка 8 / 7 → oracle 18 / 11 (до 2 поисков на вопрос) |
| размер запроса ворот | 4 400–5 200 символов | то же |

Задержка `/api/assistant/ask` внутри процесса (Apple M5, scripted-двойник отвечает мгновенно — **время модели не
входит**), мс:

|---|---|---|
| main (v1) | 24,1 / 37,8 | 30,9 / 43,7 |
| ветка (v2) | 22,4 / 41,1 | 37,3 / 51,7 |
| oracle | 24,3 / 39,6 | 35,7 / 60,0 |

Серверная часть ворот добавляет единицы миллисекунд; реальная задержка будет определяться одним дополнительным вызовом
целевой модели на вопрос «Оба» с локальными фрагментами (ограничен `EXTERNAL_GATE_TIMEOUT_SECONDS`, 20 с) и вторым
поиском MCP для двух аспектов. Эти числа для целевой модели **не измерены** (`TARGET_MODEL_NOT_VALIDATED`).
