# 02 — Решение, альтернативы и изменения

## 1. Принцип

Чинить общие механизмы, а не конкретные кейсы. Каждое изменение:

- выведено из трассы, где именно теряется факт (`01_ROOT_CAUSE_MATRIX.md`);
- измерено на tuning-manifest (184 кейса без holdout) и на 22 независимых пробах;
- принималось, только если на tuning-наборе нет регрессий `context_ok` и PASS→FAIL.

Holdout в итерациях не участвовал. Инфраструктура не менялась: нет векторной БД, embedding-сервиса, LLM-re-ranker,
новых сервисов и сетевых зависимостей. Всё — в существующем FTS5/retrieval-пайплайне, детерминированно и
объяснимо.

### 2.2 Упаковка фрагментов v2 (`backend/app/services/retrieval.py::passages`)

Лимиты прежние: 4 документа, 6 фрагментов, 1500 символов на фрагмент, бюджет контекста 12 000. Ранжирование
документов прежнее.

0. **Документ, названный в вопросе своим точным id, — предмет вопроса**: его секции упаковываются первыми (шаги 2–3),
   остальные документы получают только оставшиеся места. Правило добавлено **после** первого итогового прогона по
   регрессии E2E (R2-01/R2-02, не по holdout): на вопрос «источник и получатель потока DEMO-INT-001» v2 без правила
   упаковывал по секции четырёх похожих потоков, и ответ начинался с таблицы другого потока. Ни один кейс ассистента
   (включая holdout и пробы) не называет id документа; повторный прогон совпал с первым по каждому кейсу (`03` §0).
1. **Кандидаты** — все секции 4 документов контекста, в которых есть слово вопроса. В v1 это были 60 BM25-лучших
   секций всего корпуса, и релевантная секция документа контекста могла выпасть из-за плотных секций других
   документов (тест на 70 «плотных» документах).
2. **Первый проход** — по одной секции на документ, в порядке документов: BM25-лучшая (как v1).
3. **Оставшиеся места** заполняются по одной секции. Берётся секция с наибольшим приростом: Σ весов слов вопроса,
   которых ещё нет во фрагментах *её же* документа. Вес слова — `log((N+1)/(df+1)) + 1` по разрешённому снимку
   читателя. Слово, уже показанное из другого документа, весит 0,5; слово, которое документ уже показал
   (подтверждение), весит 0,25. Сумма делится на (1 + ранг документа). При равенстве: документ с меньшим числом
   фрагментов, затем ранг, затем BM25.

В итоге вопрос, части которого отвечены в разных секциях лучшего документа, получает эти секции. v1 всегда брал
две BM25-лучшие, часто короткие и плотные «Пример» и «Назначение». Шаблонный текст корпуса (boilerplate) по-прежнему
никогда не попадает в кандидаты. Фрагменты дословны, с id, якорем и ревизией, порядок детерминирован (тесты).

### 2.3 LOCAL_SUFFICIENCY v2 (`backend/app/services/assistant.py::local_insufficiency`)

| Правило | v1 | v2 |
|---|---|---|
| нет фрагментов; неизвестная сущность; > 1/3 слов нет в корпусе | так же | так же |
| покрытие ≥ 2/3 | одним **фрагментом** (`no_single_local_passage`) | одним **документом** по его фрагментам в контексте (`no_single_local_source`). Секции одного документа дополняют друг друга, слова, разбросанные по разным документам, — по-прежнему не ответ |
| специфическое слово | нет | документ, покрывший ≥ 2/3, обязан содержать каждое **специфическое** слово вопроса, то есть встречающееся в ≤ 10 % разрешённых документов (и хотя бы в одном). Иначе `specific_terms_not_covered` |

Данные для порога взяты только с tuning-материала (`evidence/df_external_tuning_cases.txt`). Во всех
не-holdout-кейсах, где внешний источник нужен, лучший локальный документ лишён редкого слова: «срок» (df 6 из 73),
«лимит» (df 1). Во всех кейсах, где он не нужен, редкие слова в лучшем документе есть. Частоты берутся из тех же
FTS-запросов, что уже делались для `matched_terms`, поэтому лишних запросов нет. Коды причин в API — свободная
строка; UI получил русские подписи для двух новых кодов. Старый код `no_single_local_passage` больше не
выдаётся. Тест `test_external_rag.py` обновлён на коды v2; поведение (вызов, цитата, факт) не менялось.

### 2.4 Инструменты разработчика

- `backend/app/evaluation/retrieval_trace.py` — трасса одного кейса по стадиям: термы, FTS-кандидаты, ранги,
  секции с фактами, выбранные фрагменты, контекст, решение о достаточности, ответ. Определяет стадию потери.
  Работает на временной копии синтетической базы, в логи приложения не пишет. Holdout отклоняет без
  `--allow-holdout`.
- `reports/retrieval-quality/tools/`:
  - `make_tuning_manifest.py` — tuning-only manifest;
  - `bench_assistant.py` — латентность и MCP-вызовы ask;
  - `red_check.sh` — прогон новых тестов на коде до изменения.

## 3. Рассмотренные и отвергнутые альтернативы (измерено, tuning + пробы)

| Вариант | Tuning PASS / `context_ok` | Пробы PASS / `context_ok` | Почему отвергнут |
|---|---|---|---|
| Только служебные слова (+ беглая гласная), упаковка v1 | 177 / 0,913 | 14 / 0,75 | старая упаковка с новым набором термов теряет контекст в RQ-MS-02/03 и RQ-MD-02 (хрупкость глобального топ-60) |
| Первая секция документа по покрытию слов (idf-сумма), лимит 16 | 176 / 0,913 | 14 / 0,875 | теряет контекст KE-PROC-010 (две секции с одинаковым набором слов, выбрана не та); регрессии генерации KE-GOV-010, KE-INTA-013 |
| Первая секция по числу покрытых слов | 179 / 0,9565 | 15 / 0,875 | регрессия генерации KE-INTA-013 |
| Слияние нормированных покрытия и BM25 | 175 / 0,8913 | 13 / 0,875 | хуже по всем показателям |
| Ранжирование документов контекста с учётом лучшей секции (MaxP), 8 кандидатов | 176 / 0,9348 | 13 / 0,8125 | возвращает DEMO-INT-002 в KE-INTA-012, но пускает слабые документы в no-answer-кейс KX-DISC-08 (ответ вместо «недостаточно данных»): потеря точности |
| Мягче штраф за ранг, 1/(1 + 0,5·ранг) | 179 / 0,9348 | 14 / 0,9375 | на большем tuning-наборе теряет контекст KE-SRC-013 и ответ KE-GOV-010 |
| **Выбрано:** BM25-первая + прирост покрытия (подтверждение 0,25) + лимит 16 + v2 достаточности | **180 / 0,9565** | **15 / 0,875** | без регрессий `context_ok` и PASS→FAIL на tuning-наборе |

Почему не новый компонент: все шесть причин — это анализ запроса, упаковка, правило достаточности и
лексические разрывы. Первые три решаются внутри пайплайна. Лексический парафраз (KE-SRC-004, RQ-PAR-02,
«пауза»/«задержка») без семантики закрывается только словарём. Embedding-модель или re-ranker проект исключает
сознательно (CLAUDE.md §3), и в этой задаче они не разрешены.
