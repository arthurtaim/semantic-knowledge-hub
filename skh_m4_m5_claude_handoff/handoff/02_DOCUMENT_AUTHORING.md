# 02 — Создание, редактирование, черновики и AI-assisted authoring

## Цель и UX

Действие «Создать документ» на главной и в каталоге → ручное создание или «С помощью AI» → тип → шаблон → Markdown editor + preview → сохранение черновика → валидация → предложение изменений. Пользователь не обязан понимать Git или редактировать YAML вручную.

## Минимальные метаданные

ID (стабильный и уникальный), title, document type, section, description, owner (если известен), status=`draft`, references, безопасный GitLab filepath. Предложить ID/path до отправки. Проверять ID и path и против текущих документов, и против конфликтующих незавершённых предложений. При гонке дополнительно перепроверять удалённый GitLab перед созданием файла.

## Пять типов шаблонов

| Тип | Обязательная структура |
|---|---|
| Architecture | Назначение; Контекст; Компоненты; Взаимодействия; Зависимости; Ограничения; Решения; Связанные документы |
| Integration | Назначение; Источник и получатель; Передаваемые данные/метаданные; Маппинг; Бизнес-правила; Ограничения; Ошибки; Требования |
| Business Entity | Определение; Назначение; Атрибуты; Связи; Бизнес-правила; Источники; Ограничения |
| ADR | Контекст; Проблема; Альтернативы; Решение; Обоснование; Последствия; Статус |
| Team Process | Назначение; Участники; Входы; Шаги; Ответственные; Результаты; Исключения; Связи |

Шаблоны хранить отдельно от React-компонентов, расширять через конфигурацию/добавление файла.

## Редактор и сохранение

Markdown: заголовки, списки, таблицы, ссылки, код; live preview, по возможности split desktop; mobile toggle. Frontmatter генерирует приложение из полей. Draft персистентен на backend/томе, переживает reload и перезапуск Docker. Отдельные действия Save/Resume/Delete (с подтверждением)/Validate/Submit for review. Индикатор несохранённых изменений. Не хранить черновик только в localStorage.

## Состояния

Отдельно документ (`draft`, `in_review`, `approved`, `deprecated`, согласно существующему контракту) и proposal (`draft`, `ready_for_review`, `submitting`, `submitted_to_gitlab`, `merged`, `rejected`, `conflict`, `submission_failed`). Для предложений различать `operation=create|update`. Не включать черновик в утверждённый каталог и подтверждённые AI-цитаты.

## AI-assisted authoring сейчас

Только честный **offline demo provider**: сформировать структуру по шаблону, внести лишь извлечённые из синтетических документов проверенные факты и ссылки. Любые пробелы — placeholders/«требует уточнения». Нельзя выдумывать требования и бизнес-правила или выдавать шаблон за генерацию настоящей LLM. AI предлагает текст; человек редактирует и отправляет через тот же proposal workflow.

Контракт будущей генерации: user request, template/type, retrieved references, source IDs/revisions/status, access scope, generated draft, evidence/unverified claims, warnings. Все источники недоверенные данные, не инструкции. Не реализовывать выдуманный API GigaCode.

## Acceptance

Создание, валидация, редактирование и повторное открытие draft; уникальность ID/path; Markdown safe rendering; невозможность подтверждения из draft; diff нового файла как добавление всего содержимого; UX понятен аналитику.
