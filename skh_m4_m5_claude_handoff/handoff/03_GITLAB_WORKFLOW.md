# 03 — GitLab: хранилище знаний и полный lifecycle

## Основной контракт

GitLab — source of truth для Markdown и истории изменений. Поддерживаются explicit `create`/`update`; прямой write в основную защищённую ветку невозможен. Все изменения через MR.

## Жизненный цикл `create`

1. Валидировать frontmatter, размер, путь, ID и отсутствие конфликта предложений.
2. Проверить ID/filepath в актуальной целевой ветке GitLab.
3. Получить текущий head SHA.
4. Создать уникальную рабочую ветку; не перезаписывать чужую.
5. Создать файл `create` commit action (не `update`).
6. Открыть один MR на предложение, сохранить MR ID/URL и состояние отправки.
7. Подтверждать `merged` только из фактического ответа GitLab (не из UI-флага).
8. Обновить knowledge index на новой подтверждённой ревизии, после этого создать publication job.

`update` использует аналогичный путь, но с проверкой базового SHA и `update` action. Гонка между check и write должна разрешаться конфликтом, а не перезаписью.

## Ошибки и идемпотентность

- Коллизия ID/path/branch и изменившийся head.
- 401/403/404/429/5xx, timeout, loss of response.
- После неопределённого результата commit или MR **не повторять запись вслепую** — сначала искать remote evidence. При невозможности сверки показывать статус `result_unknown`/эквивалент существующей state machine, блокировать опасные действия.
- Повторная отправка одного proposal не создаёт второй MR.
- MR создан ≠ merged; merged ≠ опубликовано.

## Синхронизация

Проверять SHA head; не перечитывать дерево, если не изменилось. Обновлять изменённые/удалённые файлы, индекс и source/revision. При сетевой ошибке показывать последний кэш как *устаревший* (если допускается текущей политикой), не утверждать актуальность. При auth-denied очищать закрытый кэш; не индексировать чужие данные в общий индекс.

## Тесты

Stateful mock GitLab: project, tree, files at revisions, branches, commits, MR, merge, conflict, delays, timeouts, lost responses, auth errors, pagination. E2E полного create → merge → sync с подтверждением SHA и индексирования. Реальный GitLab без явного разрешения не подключать.
