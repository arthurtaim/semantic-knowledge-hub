# Шаблоны документов и генерируемый frontmatter

Реализация: `backend/app/domain/templates.py`, файлы шаблонов — `backend/app/document_templates/*.md`.
Проверено тестами `backend/tests/test_authoring.py` (локально). Схема документа — `docs/DOCUMENT_SCHEMA.md`;
процесс создания — `docs/DOCUMENT_CREATION_WORKFLOW.md`.

Шаблоны хранятся отдельно от React-компонентов: UI получает их через `GET /api/authoring/templates`.
Добавить шаблон — значит добавить файл; изменения кода не нужны.

## 1. Пять встроенных шаблонов

| `template_id` | Название | `doc_type` | `id_prefix` | Теги по умолчанию | Порядок |
|---|---|---|---|---|---|
| `architecture` | Архитектура | `architecture` | `SEM-ARCH` | `architecture` | 10 |
| `integration` | Интеграция | `integration` | `SEM-INT` | `integration` | 20 |
| `business_entity` | Бизнес-сущность | `domain` | `SEM-DOM` | `domain` | 30 |
| `adr` | Архитектурное решение (ADR) | `decision` | `SEM-DEC` | `adr`, `decision` | 40 |
| `team_process` | Процесс команды | `process` | `SEM-PROC` | `process` | 50 |

Обязательные разделы (`##`, в этом порядке):

| Шаблон | Разделы |
|---|---|
| `architecture` | Назначение; Контекст; Компоненты; Взаимодействия; Зависимости; Ограничения; Решения; Связанные документы |
| `integration` | Назначение; Источник и получатель; Передаваемые данные и метаданные; Маппинг; Бизнес-правила; Ограничения; Ошибки; Требования |
| `business_entity` | Определение; Назначение; Атрибуты; Связи; Бизнес-правила; Источники; Ограничения |
| `adr` | Контекст; Проблема; Альтернативы; Решение; Обоснование; Последствия; Статус |
| `team_process` | Назначение; Участники; Входы; Шаги; Ответственные; Результаты; Исключения; Связи |

Особенности тел шаблонов: в `business_entity` раздел «Атрибуты» содержит заготовку таблицы
(Атрибут / Описание / Обязательность); в `team_process` раздел «Шаги» — нумерованный список; в `adr` раздел
«Статус» — статус **решения** (предложено / принято / заменено), а не статус документа.

`doc_type` определяет раздел каталога: `architecture` → «Архитектура», `integration` → «Интеграции»,
`domain` → «Домен», `decision` → «Решения», `process` → «Процессы».

## 2. Формат файла шаблона

Markdown-файл с небольшим YAML-заголовком. Пример (сокращён):

```md
---
template_id: adr
title: Архитектурное решение (ADR)
description: "Запись архитектурного решения: контекст, альтернативы, решение и последствия."
doc_type: decision
id_prefix: SEM-DEC
default_tags: [adr, decision]
order: 40
---
## Контекст
> Требует уточнения: ситуация, в которой принимается решение.

## Проблема
> Требует уточнения: какую проблему нужно решить.
```

| Поле | Обязательно | Правило |
|---|---|---|
| `template_id` | да | `^[a-z][a-z0-9_]{1,40}$`; уникален среди всех шаблонов |
| `title` | да | непустая строка (название в UI) |
| `description` | нет | краткое описание в карточке шаблона |
| `doc_type` | да | одно из `overview`, `architecture`, `domain`, `integration`, `process`, `decision`, `standard`, `glossary` |
| `id_prefix` | да | вида `SEM-ARCH`: `^[A-Z][A-Z0-9]*(-[A-Z0-9]+)*$` и допустимый ID документа |
| `default_tags` | нет | список строк; приводятся к нижнему регистру |
| `order` | нет | целое число, порядок в списке (по умолчанию 100; при равенстве — по `template_id`) |

Тело шаблона:

- каждый заголовок второго уровня `## …` становится **обязательным разделом** документа (в порядке появления);
  шаблон без единого `##` не загружается;
- первая строка раздела вида `> Требует уточнения: <подсказка>` — подсказка для автора; демо-AI использует её
  как пояснение к разделу (`docs/AI_AUTHORING_CONTRACT.md`);
- заголовок первого уровня в шаблон не пишется: при создании документа в начало тела подставляется
  `# <название документа>`;
- размер файла — не больше 32 КБ.

## 3. Как добавить или изменить шаблон

1. Создать файл `<template_id>.md`:
   - во встроенном каталоге `backend/app/document_templates/` (через изменение кода приложения, ревью в GitHub), или
   - в отдельном каталоге и указать его в `DOCUMENT_TEMPLATES_DIR` (абсолютный путь или путь относительно
     корня проекта). **Внимание:** при заданном `DOCUMENT_TEMPLATES_DIR` встроенный каталог не читается —
     скопируйте туда и пять встроенных шаблонов, если они нужны.
2. Перезапустить backend: шаблоны загружаются при старте.
3. Проверить `GET /api/authoring/templates`: новый шаблон в списке, `sections` совпадают с ожидаемыми,
   `suggested_id` свободен.

Загрузка устойчива к ошибкам: файл с некорректным заголовком, дубликатом `template_id`, символической ссылкой
или превышением размера пропускается с записью в журнал (`skh.templates`), остальные шаблоны работают.
Если каталог не найден или пуст, UI показывает «Шаблоны документов не найдены».

Шаблоны не должны содержать реальных банковских данных: это структура и подсказки, а не факты.

## 4. Генерируемый frontmatter

YAML пишет приложение (`compose_document`) из полей формы; пользователь YAML не редактирует. Значения
сериализуются библиотекой YAML (`yaml.safe_dump`), а не склеиваются строками: например, перевод строки
и `status: approved` внутри названия не превращаются в отдельное поле.

Порядок полей:

| # | Поле | Откуда | Правило |
|---|---|---|---|
| 1 | `id` | форма (предложен `suggested_id`) | обрезаются пробелы |
| 2 | `title` | форма | |
| 3 | `type` | **шаблон** (`doc_type`) | из формы не принимается |
| 4 | `status` | форма | по умолчанию `draft`; `deprecated` запрещён; `approved` — предупреждение (ошибка для AI-черновика) |
| 5 | `owner` | форма | |
| 6 | `tags` | форма | в нижнем регистре, без пустых и дубликатов (UI подставляет `default_tags` шаблона) |
| 7 | `related_ids` | форма | без пустых и дубликатов |
| 8 | `source_refs` | форма | без пустых и дубликатов |
| 9 | `summary` | форма | только если заполнено; пробелы схлопываются в одну строку |
| 10 | `reviewed_at` | всегда `null` | дату проверки ставит ревью, а не автор черновика |

Пример результата:

```md
---
id: SEM-ARCH-002
title: Контур метаданных
type: architecture
status: draft
owner: semantic-team
tags: [architecture]
related_ids: [SEM-ARCH-001]
source_refs: []
reviewed_at: null
---

# Контур метаданных

## Назначение
> Требует уточнения: какую задачу решает система или компонент и для кого.
…
```

Поле `confluence_page_id` в форму не входит. Если оно появится в документе (например, через правку
существующего файла), публикация его **игнорирует** (`docs/CONFLUENCE_MAPPING.md`).

## 5. Пометка «Требует уточнения»

`Требует уточнения` — единая пометка незаполненного места. Её ставят шаблоны и демо-AI. Пока пометки
остаются, проверка выдаёт предупреждение `unresolved_placeholders` с их количеством. Это не блокирует
сохранение и ревью: решение, можно ли отправлять неполный документ, принимает автор и ревьюеры GitLab.

## 6. Предупреждения и ошибки, связанные с шаблоном

| Код | Уровень | Когда |
|---|---|---|
| `template_section_missing` | предупреждение | в теле нет одного или нескольких обязательных разделов (сравнение заголовков `##` без учёта регистра) |
| `unresolved_placeholders` | предупреждение | в теле остались «Требует уточнения» |
| `template_type_mismatch` | ошибка | `type` документа не совпадает с `doc_type` шаблона |
| `template_not_found` | `404` | указан несуществующий `template_id` |

Общие проверки документа (ID, путь, размер, секреты, статусы) — `docs/DOCUMENT_CREATION_WORKFLOW.md`, раздел 7.
