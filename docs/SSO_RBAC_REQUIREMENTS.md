# Требования к будущим SSO и RBAC

Сейчас реализованы только **точки применения** авторизации (`backend/app/authz.py`). Аутентификации
нет. Единственная рабочая политика — `LocalDemoPolicy`: один оператор на loopback.

## 1. Где принимается решение

Каждый маршрут `/api/*`, кроме `/api/health`, объявляет действие через `Depends(require(Action.X))`.
Тест `tests/test_authz.py` проверяет:
- у каждого маршрута ровно одно действие;
- действия на запись именно те, что указаны в таблице ниже;
- `DenyAllPolicy` отказывает (403) на всех маршрутах;
- доступ к корпоративным источникам требует отдельного права, даже внутри поиска и ассистента.

| Action | Маршруты | Что должна проверять политика |
|---|---|---|
| `read_knowledge` | `GET /api/documents*`, `/api/knowledge/*`, `/api/search` (team), `GET /api/drafts*` | право читать документы. После PB-03 — **по каждому документу**: результаты, поиск, цитаты и предложения фильтруются по ACL GitLab пользователя |
| `read_corporate` | `GET /api/corporate/pages/*`, а также `search`/`ask` с `corporate` | Confluence ACL пользователя; при сервисном токене — недостижимо (PB-04) |
| `ask_assistant` | `POST /api/assistant/ask` | право пользоваться ассистентом; доказательства — только из документов, разрешённых по `read_knowledge` и `read_corporate` |
| `view_system` | `/api/session`, `/api/integrations/status`, `/api/index/status` | без чувствительных данных; детали интеграций — администраторам |
| `create_proposal` | `POST /api/drafts`, `POST /api/drafts/suggest` | роль «редактор» для раздела документа |
| `review_proposal` | `mark-ready`, `reject` | автор или редактор раздела; отклонение чужого — только владелец раздела |
| `submit_proposal` | `submit`, `open-mr`, `refresh-status` | право создавать ветки и MR в проекте знаний. Ветка и MR создаются **от имени пользователя** (или с атрибуцией), а не сервисной учётной записью |
| `sync_knowledge` | `POST /api/index/sync` | администратор или сервис |

## 2. Аутентификация (SSO)
- Корпоративный IdP по OIDC или SAML, терминируемый на reverse proxy или в приложении. Решение за ИБ.
- Идентичность пользователя: стабильный ID, отображаемое имя, группы. Заголовки от прокси принимаются только
  с доверенного адреса и с подписью или mTLS.
- Сессии: короткоживущие, `Secure`, `HttpOnly`, `SameSite=Strict`, выход и отзыв. Сохраняется CSRF-защита
  (`X-SKH-Client` + проверка `Origin`).
- Отказ IdP → отказ в доступе (fail closed). Анонимного или «гостевого» режима нет.

## 3. Модель ролей (предложение для согласования)

| Роль | Права |
|---|---|
| Читатель | `read_knowledge`, `ask_assistant`, `view_system` (без деталей) |
| Читатель корпоративных источников | + `read_corporate` (при наличии пользовательского ACL Confluence) |
| Редактор раздела | + `create_proposal`, `review_proposal` для своих разделов |
| Публикатор | + `submit_proposal` |
| Администратор | + `sync_knowledge`, детали интеграций |

Права на разделы берутся из GitLab: CODEOWNERS или участники проекта. Приложение не должно стать вторым,
расходящимся источником прав.

## 4. Данные и индекс
- Общий поисковый индекс, построенный сервисной учётной записью, нельзя показывать пользователям с разными
  правами. Возможные варианты: фильтрация результатов по ACL на запрос, отдельные индексы по группам
  доступа, проверка права на каждый документ перед выдачей. Вариант выбирается вместе с ИБ.
- Цитаты и выдержки в ответах ассистента — тоже данные: их фильтрация обязательна до передачи модели.
- Предложения содержат текст документа и видны только тем, кто может читать документ.

## 5. Аудит (минимум)
Вход и выход, отказ в доступе (403), чтение документа и страницы Confluence, вопрос ассистенту
(без текста — по решению ИБ), создание, отклонение и отправка предложения, создание MR, ручная
синхронизация. Хранение и доставка — по требованиям ИБ (PB-07).

## 6. Обязательные тесты при внедрении
- Каждое действие: разрешено нужной роли и запрещено остальным (матрица из раздела 3).
- Пользователь без доступа к документу не видит его в списке, поиске, цитатах, предложениях и через `/api/documents/{id}`.
- Отзыв прав в GitLab или Confluence действует не позже TTL кэша.
- Подделка заголовков идентичности напрямую (в обход прокси) отклоняется.
