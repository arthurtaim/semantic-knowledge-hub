# «Работа»: проекты и задачи — руководство пользователя

Короткая инструкция для аналитиков и инженеров. Технический контракт — `docs/WORK_MANAGEMENT.md`. Все примеры —
синтетические демо-данные.

## Режим работы

Вверху каждого экрана — строка режима:

- **«Локальная демонстрация — один оператор»** — вы единственный пользователь этого стенда; можно всё. Исполнители
  с пометкой «(демо)» — вымышленная команда для примера (3 аналитика, руководитель проекта, 2 разработчика), а не
  учётные записи: назначение никому не даёт прав. Меню «Исполнитель» показывает роль каждого и сколько задач проекта
  на нём — так видно распределение работы.
- **«Демо-стенд — общий вход, один пользователь»** — вы вошли на демо-стенд по общему логину: можно всё, как
  локальному оператору. Все, кто входит по этому логину, — один и тот же пользователь: в истории изменений не видно,
  кто именно из команды что поменял.
- **«Только просмотр — изменения задач отключены»** — стенд открыт по общей ссылке: смотреть можно, менять нельзя
  (кнопок изменения нет вовсе). Это сделано намеренно: общий пароль не определяет, кто именно работает.

## Проекты и задачи

1. «Проекты» в группе «Работа» → карточки проектов: прогресс, просрочка, задачи без дат, ближайшая веха.
2. «Создать проект»: ключ (латиница, например `ARIS`, не меняется — с него начинаются ключи задач `ARIS-12`),
   название, сроки.
3. В проекте — «Задача» (или «Добавить подзадачу» в карточке задачи): название, исполнитель, приоритет, сроки
   («Без дат», «Начало и длительность», «Веха»), срок (дедлайн).
4. Виды «Список | Доска | Гант» показывают одни и те же данные; ревизия плана в шапке одинакова во всех видах.
   - **Список**: правка на месте — название, статус, исполнитель, приоритет, даты.
   - **Доска**: перетаскивание карточки в колонку меняет статус; с клавиатуры — Alt + ← / → или меню «Сменить статус».
   - **Гант**: перетаскивание полосы сдвигает задачу, правый край — длительность; с клавиатуры — ← / → и Shift + ← / →,
     Enter — предпросмотр. Ничего не меняется до «Применить»: сначала видно, какие зависимые задачи сдвинутся.
5. Зависимости «окончание → начало» — в карточке задачи. Цикл сервер не допустит и покажет его путь.
6. Даты: рабочие дни Пн–Пт; в интерфейсе — последний рабочий день задачи (включительно). Срок (дедлайн) отдельно от
   плана: планировщик его не меняет, только предупреждает.

## Документы задачи

В карточке задачи — раздел **«Документы»**:

- **«Связать с документом»** → начните вводить ID или название → выберите документ → вид связи (Реализует, Опирается на,
  Документирует, Проверяет, Блокирует) → «Связать». Предлагаются только документы, которые вам доступны.
- Ссылка ведёт на страницу документа; рядом — его статус и версия.
- **«Документ изменён после связывания»** — документ обновился. Проверьте, не затронута ли задача, и нажмите
  **«Проверено»** — связь запомнит новую ревизию. Сама система ничего не «переутверждает» и задачу не меняет.
- **«Документ устарел (deprecated)»** и **«Не утверждён»** — документ не является авторитетным источником.
- **«Документ недоступен — удалён или нет доступа»** — документ удалили или у вас нет к нему доступа; что это за
  документ, намеренно не показывается. Такую связь можно убрать.
- **«Не проверено: база знаний сейчас недоступна»** — задачи работают как обычно, просто документы сейчас не
  проверить.

На странице документа: вкладка **«Связи» → «Задачи»** — задачи, связанные с документом (только из доступных вам
проектов), и ссылка «Задачи проекта … по документу». В проекте фильтр **«Документ»** оставляет в Списке, на Доске и на
Ганте только задачи, связанные с выбранным документом.

## «AI план» (если подключена языковая модель)

Кнопка **«AI план»** рядом с «Задача» видна, только если на стенде подключена модель и у вас есть право изменять
проект. В режиме без модели кнопки нет — всё остальное работает.

1. «AI план» → опишите, что нужно («по спецификации интеграции подготовь задачи на 4 недели»), выберите до пяти
   документов (или оставьте пусто — сервер возьмёт утверждённые документы по запросу) и, при желании, плановое начало
   → «Подготовить предложение».
2. Откроется **проверка предложения**. Ничего ещё не создано. Видно:
   - источники — документы с их статусами (черновик назван черновиком);
   - допущения модели;
   - «Проверка сервера» — что сервер отбросил или о чём предупреждает: модель попыталась назначить исполнителя или
     поставить даты, сослалась на документ, которого не было, привела цитату, которой в документе нет; нет оценки;
     похожая задача уже есть;
   - задачи: снимите галочку, чтобы не создавать; исправьте название, приоритет, оценку; выберите исполнителя;
   - зависимости: снимите лишние;
   - даты, рассчитанные сервером от начала по рабочим дням («Пересчитать сроки»).
3. **«Создать задачи (N)»** — всё создаётся одной операцией: задачи, зависимости и связи с подтверждёнными
   источниками. **«Отклонить»** — ничего не создаётся.
4. Если план проекта или документы-источники изменились, предложение **устарело** — применить его нельзя;
   «Подготовить заново».

## Вопросы ассистенту о задачах

На главной или в «Ассистенте» (с подключённой моделью) можно спросить: «Какие задачи ARIS просрочены?», «Каков статус и
риски задач RAG?», «Что с задачей ARIS-6?». Ответ опирается только на данные модуля «Работа» — карточка «По данным
модуля «Работа» SKH» со ссылками на задачи. Менять задачи из чата нельзя.

## Чего нет (пока)

Комментарии к задачам, критический путь, лаг в зависимостях и типы кроме «окончание → начало», праздники в календаре,
внешние ссылки на Confluence/GitLab из задач, командный режим с настоящей идентификацией пользователей.
