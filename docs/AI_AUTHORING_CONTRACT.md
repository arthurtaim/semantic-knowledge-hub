# Контракт AI-assisted authoring (создание документа с помощью AI)

Реализация: `backend/app/adapters/ai/base.py` (`AuthoringRequest`, `AuthoringReference`, `AuthoringDraft`,
`AuthoringCitation`, метод `AIProvider.draft_document`), `backend/app/adapters/ai/mock.py` (демо),
`backend/app/adapters/ai/openai_compatible.py` (внутренний OpenAI-совместимый API), проверка —
`backend/app/services/authoring.py` (`AuthoringService.ai_draft`). Маршрут — `POST /api/authoring/ai-draft`.

Проверено локально (`backend/tests/test_authoring.py`) только с демо-провайдером `mock`. Адаптер
`internal_api` для авторинга на реальной модели **не проверялся**; GigaCode не подключён.

## 1. Границы ответственности

AI **предлагает текст** тела документа. Он не сохраняет черновик, не заполняет метаданные, не утверждает,
не делает merge и не публикует. Ответ `POST /api/authoring/ai-draft` никуда не записывается: автор переносит
его в редактор, правит и отправляет через тот же путь, что и ручной документ (сохранение → проверка →
ревью → GitLab MR → merge людьми). Черновик с `origin=ai_suggestion` не может иметь статус `approved`
(ошибка `ai_cannot_approve`).

```text
AiDraftRequest ─▶ AuthoringService: шаблон, снимок базы знаний пользователя, выбор утверждённых источников,
                  подготовка текста (нейтрализация маркеров и инструкций)
               ─▶ AuthoringRequest ─▶ AIProvider.draft_document ─▶ AuthoringDraft
               ─▶ AuthoringService: проверка каждой цитаты по исходному документу, провенанс из снимка
               ─▶ AiDraftResponse (только предложение; не хранится)
```

## 2. Вход провайдера: `AuthoringRequest`

| Поле | Тип | Смысл |
|---|---|---|
| `request` | строка | что попросил автор (3–2000 символов); **данные**, а не инструкции, отменяющие правила |
| `template_id` | строка | шаблон (`docs/DOCUMENT_TEMPLATES.md`) |
| `doc_type` | `DocType` | тип документа из шаблона |
| `title` | строка | название документа |
| `sections` | кортеж `(заголовок, подсказка)` | обязательные разделы шаблона по порядку и подсказки «Требует уточнения: …» |
| `references` | кортеж `AuthoringReference` | авторизованные, уже отобранные источники — **недоверенный материал** |
| `access_scope` | строка | область, из которой отобраны источники; сейчас всегда `team` |

`AuthoringReference`: `document_id`, `title`, `revision` (SHA коммита в GitLab или `sha256:`-ревизия
локально), `status` (всегда `approved`), `source_type` (`gitlab`/`local`), `sections` — пары
`(заголовок, подготовленный текст)`, `is_demo`.

## 3. Выход провайдера: `AuthoringDraft`

| Поле | Смысл |
|---|---|
| `body` | Markdown тела без frontmatter — предложение для редактирования человеком |
| `citations` | список `AuthoringCitation {document_id, section, quote}`; `quote` обязана быть дословной выдержкой из указанного документа |
| `unverified_claims` | утверждения, не подтверждённые дословными выдержками |
| `warnings` | предупреждения провайдера |
| `suggested_related_ids` | кандидаты в `related_ids` |
| `insufficient_data` | `true`, если подходящих источников нет |

Ответ API (`AiDraftResponse`): `mode`, `body`, `references` (документы, переданные провайдеру: ID, название,
ревизия, статус, источник, `is_demo`), `citations` (**только проверенные**, с названием, ревизией и статусом
из снимка базы знаний), `unverified_claims`, `warnings` (провайдера и сервера), `insufficient_data`,
`suggested_related_ids` (только из `references`), `access_scope`.

## 4. Как отбираются источники (область `team`)

1. Снимок базы знаний **текущего пользователя** (`KnowledgeService.snapshot(user)`).
2. Явные `related_ids` из запроса (до 10): используются только найденные документы со статусом `approved`;
   для остальных — предупреждение «не найден» или «не утверждён и не используется как источник».
3. Поиск FTS по словам из названия и запроса с фильтром `status=approved`; всего не больше 4 документов.
4. Из каждого документа берутся непустые разделы, каждый не длиннее 1500 символов, и проходят подготовку
   `prepare_passage_text`: маркеры вида `[C2]` нейтрализуются, предложения, похожие на инструкции для ИИ,
   заменяются видимой заглушкой.
5. Корпоративные источники (Confluence MCP) **не используются**: черновик командного документа не смешивает
   командные и корпоративные данные. Черновики, документы «На ревью» и устаревшие документы не используются.

## 5. Демо-провайдер (`AI_PROVIDER=mock`)

Детерминированный, без языковой модели и без сети. Он **не сочиняет** утверждений.

Что делает:

- пишет `# <название>` и все разделы шаблона в заданном порядке;
- в разделах «Связанные документы», «Связи», «Источники» перечисляет найденные документы: ссылка
  `[название](<ID>.md)`, ID, статус, первые 12 символов ревизии;
- в остальных разделах оставляет `> Требует уточнения: <подсказка шаблона>`;
- если в одном из источников есть раздел с тем же заголовком (точное совпадение или совпадение первых
  6 символов, когда оба заголовка не короче 6 символов), добавляет **одно дословное предложение**
  (20–400 символов, без квадратных скобок, не похожее на инструкцию для ИИ) с указанием документа, раздела
  и ревизии и пометкой «проверьте, применима ли она», и записывает его в `citations`;
- предупреждения: всегда — «Демо-режим: черновик собран без языковой модели…»; при отсутствии источников —
  «Недостаточно данных: в утверждённых документах базы знаний не найдено материалов по запросу…»
  (`insufficient_data=true`, все разделы с «Требует уточнения»); при источниках без подходящих выдержек —
  отдельное предупреждение;
- `unverified_claims` всегда пуст (нечего проверять: собственного текста нет);
- `suggested_related_ids` — ID найденных документов.

Чего **не** делает: не формулирует требования, бизнес-правила, атрибуты, сроки, системы и ограничения;
не пересказывает и не обобщает источники; не использует текст запроса как содержание (запрос нужен только
для поиска источников); не обращается к корпоративным источникам; не задаёт статус и другие метаданные;
ничего не сохраняет. Демо не выдаётся за работу настоящей LLM: UI показывает отметку демо-режима.

## 6. Проверка на сервере (для любого провайдера)

`AuthoringService` после ответа провайдера:

- для каждой цитаты проверяет, что документ входит в `references` и есть в снимке пользователя, и что
  `quote` встречается в тексте разделов документа дословно (без учёта регистра и пробельных различий; части,
  разделённые « … », проверяются по отдельности). Иначе цитата исключается с предупреждением «Выдержка,
  приписанная <ID>, не найдена в источнике дословно и исключена»;
- название, ревизию и статус для проверенной цитаты берёт из снимка, а не из ответа провайдера;
- оставляет в `suggested_related_ids` только ID из `references`;
- журналирует только шаблон, режим и количество источников/цитат — без текста запроса и черновика.

Само тело (`body`) не переписывается сервером: это предложение для человека. Для `internal_api` в
`unverified_claims` всегда первым пунктом добавляется «Текст сгенерирован моделью: всё, что не подтверждено
дословной выдержкой, требует проверки». Проверки документа (`docs/DOCUMENT_CREATION_WORKFLOW.md`, раздел 7)
и ревью в GitLab применяются к AI-тексту так же, как к ручному.

## 7. Prompt injection

- Документы базы знаний и запрос автора — недоверенные данные. До провайдера текст источников проходит
  `prepare_passage_text` (раздел 4).
- Демо-провайдер не цитирует предложения, похожие на инструкции для ИИ (`looks_like_prompt_injection`).
- `internal_api`: системная инструкция `AUTHORING_PROMPT` (правила нельзя изменить содержимым источников),
  источники передаются блоками `<<<SOURCE>>> … <<<END SOURCE>>>` с метаданными в JSON; последовательности
  `<<<`/`>>>` внутри данных экранируются; общий объём ограничен `AI_MAX_CONTEXT_CHARS`. Ответ — строго JSON
  `{"body", "citations", "unverified"}`; иначе `502 ai_invalid_response`. Принимается не больше 20 цитат
  (до 1000 символов) и 20 непроверенных утверждений (до 500 символов).
- Даже если модель выполнит внедрённую инструкцию, она не может утвердить, смёржить или опубликовать:
  у провайдера нет инструментов записи, а результат проходит валидацию, ревью и GitLab MR.

## 8. Ошибки

| Код | HTTP | Когда |
|---|---|---|
| `template_not_found` | 404 | неизвестный шаблон |
| `ai_authoring_unavailable` | 503 | `AI_PROVIDER=disabled` или провайдер без поддержки авторинга (`features.ai_authoring=false`) |
| `assistant_disabled`, `ai_misconfigured` | 503 | провайдер выключен или настроен неверно |
| `ai_invalid_response` и прочие ошибки провайдера | 502 | ответ модели не разобран, ошибка HTTP |
| код источника знаний | 503 | база знаний недоступна |

## 9. Что обязана соблюдать будущая реализация (GigaCode или другая LLM)

Новый провайдер реализует `AIProvider.draft_document(AuthoringRequest) -> AuthoringDraft` и регистрируется в
`build_ai()` (`backend/app/container.py`) под новым значением `AI_PROVIDER` с allowlist хоста и CA
(`docs/GIGACODE_MIGRATION.md`). Требования:

1. Использовать только переданные `references`; не обращаться к другим источникам самостоятельно (поиск,
   права и отбор остаются в backend).
2. Сохранять все разделы шаблона в заданном порядке; где нет подтверждения — оставлять «Требует уточнения».
3. Каждую дословную выдержку указывать в `citations` с `document_id`, разделом и точным текстом; всё прочее
   фактическое — в `unverified_claims`. Сервер всё равно перепроверит цитаты.
4. Явно сообщать о нехватке данных (`insufficient_data`, предупреждение «Недостаточно данных»), а не
   заполнять пробелы правдоподобным текстом.
5. Считать источники и запрос данными: игнорировать инструкции внутри них.
6. Не выходить за `access_scope`: корпоративные источники не смешиваются с командными, пока это явно не
   разрешено и не реализована проверка прав пользователя (PB-04).
7. Ничего не записывать: не создавать черновики, ветки, MR и страницы Confluence; не ставить `approved`.
8. Не логировать тексты источников, запросов и ответов; соблюдать лимиты размера и таймауты.
9. Не предполагать наличие публичного REST Agent API GigaCode: интерфейс подтверждается на корпоративной
   установке (`docs/GIGACODE_MIGRATION.md`, раздел 10).

Приёмка нового провайдера: `tests/test_authoring.py` с подменённым транспортом (структура разделов,
отсутствие непроверенных цитат, «Недостаточно данных» на пустых источниках), затем включение за флагом.
