# Задание для Claude Code: раздел «Документы» v2 — дерево, обзор, таблица

Ты начинаешь без контекста прошлых сессий. Всё нужное — в репозитории и в папке `docs-v2-handoff/`.
Работай самостоятельно, малыми срезами: изучи, реализуй, проверь, закоммить, отчитайся.

## Цель

Раздел «Документы» (`/documents`, `ExplorerPage`) неудобен для навигации:
- длинный список по 20 на страницу, около 4 документов на экран;
- одинаковое «Утверждён» в каждой строке;
- структура видна только через фильтры, нет предпросмотра.

Сделать по макетам (`screens/design/`) и спецификации `specs/DOCUMENTS_V2.md`:
1. **Список** с деревом, как в Confluence: разделы → группы → документы, список ветки и предпросмотр. Это
   вид по умолчанию.
2. **Обзор**: двумерная таблица «разделы × состояние» и блок «Что сделать».
3. **Таблица**: плотная, сортируемая, с фильтрами и колонками «Системы», «Проверен», «Связи».

Группы в дереве вычисляются автоматически (вариант 1, выбран владельцем) по правилу из спецификации §4.

## 0. Ветка — первым делом

1. `git status --short`. Допустимы только неотслеживаемые папки владельца (`Claude outputs/`, `m56/`,
   `m57_final/`, `m6/`, `addendum_m563/`, `ui-v2-handoff/`, `docs-v2-handoff/`). Изменённые отслеживаемые
   файлы — остановись и сообщи.
2. `git switch main && git pull --ff-only origin main`, затем `git switch -c feature/documents-v2`.
3. В работе ещё не влитые ветки `feature/publications-page` и `feature/m57-ai-native-tools-final`. **Не
   вливай их** в свою ветку. Если за время работы обновится `main` — влей `main` в свою ветку (merge, не
   rebase), разреши конфликты, проверь тесты.
4. Запрещено: `git add -A` / `git add .`, коммит папок владельца, merge в `main` и другие ветки, force push.
5. Первый коммит: скопируй `docs-v2-handoff/` в `docs/ui-v2/documents/` (с PNG и `design-source/`),
   сообщение `docs(ui-v2): documents section handoff`.

## 2. Срезы (по порядку; каждый — коммит с тестами)

1. **Бэкенд: правило групп и `GET /api/documents/tree`**, плюс `summary` и `systems` в списке (§4).
   - pytest на точную раскладку демо-данных: ARIS 8, CATIA 2, CRM 1, ERP 1, Data Catalog 1, Общие
     правила 6; Стандарты — 5 шаблонов и 14 регламентов.
   - Тесты на `attention_total = 12` и права доступа.
2. **Каркас вида**: сегменты `Обзор | Список | Таблица | Карта`, состояние в URL, запоминание вида.
   «Список» по умолчанию.
3. **Дерево**: компонент `DocTree` с APG-клавиатурой, фильтром, «Свернуть всё», запоминанием раскрытия,
   раскрытием до `doc=` из URL.
4. **Список ветки и предпросмотр**: строки в 3 строки, статус только у неутверждённых, сортировка, поиск
   в средней колонке, предпросмотр с TOC и кнопками; хлебные крошки на странице документа по дереву.
5. **Обзор**: матрица и «Что сделать», клетки ведут в таблицу с фильтрами.
6. **Таблица**: фильтры, сортировка, группировка, колонки, «Только требующие внимания».
7. **Адаптив и доступность**: листы на средней ширине, экраны на телефоне, тёмная тема, фокус,
   `aria-*`.
8. **Документация**: раздел «Документы v2» в `docs/UI_REDESIGN.md` — что сделано, отклонения от
   макетов, клавиатура.

## 3. Правила

- Русский UI, идентификаторы на английском. Никаких выдуманных чисел: все счётчики — из API.
- Визуальная система UI v2:
  - только токены;
  - одна основная кнопка на вид;
  - без капса, градиентов, стрелок в тексте кнопок;
  - статус — текстом и формой, не только цветом.
- Без новых зависимостей. Дерево, меню и виртуализацию сделать своими компонентами. Если без зависимости
  не обойтись — остановись и спроси.
- API: только добавления из спецификации §4. Существующие контракты не менять. Права доступа — через
  существующие сервисы.
- Существующие возможности каталога сохранить (§5 спецификации). Тесты, которые опираются на старую
  разметку, обновлять в том же коммите с объяснением; покрытие не уменьшать.

## 4. Проверка (после каждого среза; в отчёт — фактический вывод)

```bash
cd frontend && npx tsc --noEmit -p tsconfig.json && npx eslint . && npx vitest run
npx playwright test --project=desktop --project=mobile
npx playwright test --project=gitlab-mock --project=gitlab-mock-mobile
cd .. && make test-backend
```

Скриншоты «до» и «после»:
- виды Обзор, Список, Таблица;
- 1440×900, 1100×800 и 390×844;
- светлая и тёмная темы.

Сравни с `screens/design/` и исправь расхождения. Скриншоты не коммить.
