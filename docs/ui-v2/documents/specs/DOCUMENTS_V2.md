# Раздел «Документы» v2: дерево, обзор, таблица

Макеты: `screens/design/docs-01…04.png`.

## Проблема

- Из 83 документов 73 утверждены. Почти каждая строка повторяет «Утверждён». 12 документов, которым нужно
  внимание, тонут в длинном списке.
- В «Списке» помещается около четырёх документов на экран (крупная выдержка плюс строка подписей), он
  разбит на страницы по 20.
- Ориентироваться можно только фильтрами: нет структуры, нет предпросмотра, документ приходится
  открывать, чтобы понять, что в нём.

## Виды (сегменты в панели инструментов)

`Обзор | Список | Таблица | Карта`.
- По умолчанию открывается **Список**. Выбор вида запоминается (localStorage, обёрнуто в try/catch).
- Состояние в URL: `/documents?view=list|overview|table&node=<ключ>&doc=<ID>&q=…` плюс фильтры таблицы.
  Ссылку можно отправить коллеге, кнопка «Назад» работает.
- «Карта» — существующий переход на `/graph`.

## 1. Список: дерево, список ветки, предпросмотр (`docs-01`, `docs-02`)

Три колонки внутри рабочей области:

```
┌ Дерево 300 ──────────┬ Список ветки 400–480 ──────┬ Предпросмотр (остаток) ─┐
│ [Фильтр дерева] [⇡]  │ Интеграции / ARIS  8       │ статус  ID              │
│ Все документы     83 │ ┌──────────────────────┐   │ Заголовок 22/28         │
│ Требуют внимания  12 │ │ Название    Черновик │   │ summary                 │
│ ──────────────────── │ │ summary в 1 строку…  │   │ [Открыть] [Спросить…]   │
│ › Продукт          1 │ │ ID              дата │   │ [Предложить изменение]  │
│ ⌄ Интеграции  (3) 19 │ └──────────────────────┘   │ Расположение, Системы,  │
│   ⌄ ARIS      (3)  8 │ …                          │ Владелец, Проверен,     │
│     ▯ ARIS → Catalog │                            │ Связи                   │
│     ◌ Расписание v2  │                            │ теги                    │
│   › CATIA          2 │                            │ Разделы документа (TOC) │
└──────────────────────┴────────────────────────────┴─────────────────────────┘
```

### Дерево (как в Confluence)

- Сверху: поле «Фильтр дерева» (по названию и ID; совпадения подсвечены, их предки раскрыты), кнопка
  «Свернуть всё», затем «Все документы 83» и «Требуют внимания 12», разделитель.
- Уровни: раздел → группа (если у раздела есть группы, см. §4) → документ.
- Порядок разделов логический, не по числу: Продукт, Архитектура, Домен, Системы-источники, Интеграции,
  Датасеты, Процессы, Решения, Стандарты, Руководства, Глоссарий. Если API вернёт неизвестный тип — в
  конец.
- У раздела и группы: шеврон, название (раздел — вес 500), жёлтый счётчик требующих внимания (если > 0),
  общее число.
- У документа: значок по статусу и название в одну строку с многоточием, полное название — в
  подсказке:
  - утверждён — серый значок файла;
  - на ревью — фиолетовая точка;
  - черновик — пунктирный круг;
  - устарел — короткое тире и зачёркнутое название.
- Клик по разделу или группе раскрывает её и показывает её документы в средней колонке. Повторный клик
  по уже выбранной раскрытой ветке сворачивает её.
- Клик по документу выбирает его: подсветка в дереве и в списке, предпросмотр справа.
- Раскрытые ветки запоминаются. При открытии по ссылке `doc=` дерево раскрывается до документа и
  прокручивает его в видимую область.
- Клавиатура по шаблону APG Tree View:
  - ↑ ↓ — перемещение;
  - → раскрыть или войти, ← свернуть или к родителю;
  - Home / End — в начало и конец;
  - Enter — выбрать;
  - поиск по первым буквам.
  
  Роли `tree` / `treeitem` / `group`, `aria-expanded`, `aria-selected`, `aria-level`.

### Список ветки

- Заголовок: путь («Интеграции / ARIS»), число, сортировка (меню): «Сначала требующие внимания» (по
  умолчанию), «По названию», «По дате проверки».
- Строка документа (3 строки, около 72 px):
  1. Название (500, 14 px) и справа статус — **только если не «Утверждён»**: «Черновик», «На ревью»,
     «Устарел» своими цветами. Устаревший зачёркнут.
  2. `summary` в одну строку с многоточием. Если `summary` нет — строку не показывать.
  3. Мелко: ID, система или поток (если есть), справа дата проверки. Просроченная или «не проверялся» —
     янтарным.
- Выбранная строка — зелёная подложка `--accent-wash`. ↑ ↓ — по списку, Enter — открыть документ,
  Space — показать в предпросмотре.
- **Без постраничной разбивки** до 500 документов в ветке. Больше 200 строк — виртуализация или
  `content-visibility: auto`. Надписи «показаны первые N» в макете нет и не должно быть.
- Поиск в панели инструментов: при вводе средняя колонка показывает результаты поиска по всей базе
  (существующий `/api/search` с подсветкой и причинами совпадения), заголовок «Результаты: «…»». Дерево
  при этом остаётся, а ветка, в которой лежит выбранный результат, подсвечивается.

### Предпросмотр

- Данные из `GET /api/documents/{id}`: статус, ID, версия, заголовок, `summary`, свойства (Расположение в
  дереве, Системы, Владелец, Проверен, Связи = `link_count` со ссылкой на вкладку «Связи»), теги, «Разделы
  документа» (заголовки уровня 2 из `sections`, ссылки на `/documents/{id}#anchor`).
- Кнопки:
  - «Открыть» (primary);
  - «Спросить ассистента» — открывает ассистента с этим документом как контекстом, как «@документ»;
  - «Предложить изменение» — существующий маршрут.
- Пока грузится — скелет; ошибка — короткое сообщение с повтором.
- Путь на странице документа (хлебные крошки) повторяет дерево: «Документы / Интеграции / ARIS / …».

### Ширина и телефон

- Меньше 1280 px: предпросмотр выезжает листом справа по выбору документа; дерево и список остаются.
- Меньше 960 px: дерево сворачивается в кнопку «Разделы» (лист слева).
- Телефон: экран 1 — дерево; выбор ветки открывает экран 2 со списком; выбор документа сразу открывает
  страницу документа. Кнопка «Назад» в панели инструментов.

## 2. Обзор: разделы × состояние (`docs-03`)

- Заголовок «83 документа, 73 утверждены» и справа «12 требуют внимания». Под ним одна строка пояснения.
- Таблица (сетка с ролями `table` / `row` / `cell`):
  - строки — разделы в порядке дерева;
  - столбцы: Всего, Утверждено (число плюс полоска доли), На ревью, Черновики, Устарели, Нужна проверка
    (`review_state` stale или never_reviewed), Без владельца;
  - итоговая строка.
- Нулевые клетки — бледное «—»; ненулевые — цветная плашка своего тона (как статусы). Клик по клетке
  открывает **Таблицу** с фильтрами Раздел = строка, Состояние = столбец. Клик по разделу — Список с
  раскрытым разделом.
- `aria-label` у клетки: «Интеграции: 2 черновика».
- Справа «Что сделать» — те же документы, сгруппированные по действию:
  - Завершить ревью (`in_review`);
  - Назначить владельца (`owner_missing`);
  - Перепроверить (утверждённые со `stale` или `never_reviewed`);
  - Черновики и устаревшие.
  
  В каждой группе до 3 документов и «Ещё N».
- Один документ может попасть в несколько столбцов — об этом сказано в пояснении.
- Всё считается на клиенте из данных дерева (§4); отдельный API не нужен.

## 4. Данные (бэкенд, только добавления, с тестами)

### `GET /api/documents/tree` (новый)

Лёгкое дерево всей базы за один запрос, без пагинации:

```json
{
  "total": 83,
  "attention_total": 12,
  "sections": [
    {
      "key": "integration", "label": "Интеграции", "count": 19, "attention": 3,
      "groups": [
        { "key": "integration/aris", "label": "ARIS", "count": 8, "attention": 3, "doc_ids": ["DEMO-INT-001", "…"] }
      ],
      "doc_ids": []
    }
  ],
  "documents": {
    "DEMO-INT-001": {
      "title": "ARIS → Catalog: обзор потока (демо)", "status": "approved", "review_state": "ok",
      "owner": "demo-integration-team", "owner_missing": false, "reviewed_at": "2026-10-16",
      "summary": "…", "systems": ["ARIS", "Data Catalog"], "link_count": 7, "is_demo": true, "group": "integration/aris"
    }
  }
}
```

- `attention` у документа: `status` ∈ {in_review, draft, deprecated} **или** `review_state` ∈ {stale,
  never_reviewed} **или** `owner_missing`.
- Права доступа и фильтр видимости — те же, что у `GET /api/documents` (через существующий сервис, без
  обхода).
- Порядок: разделы — как в §1; группы — по названию, «Общие правила» последней; документы в группе —
  сначала требующие внимания, затем по названию.

### Правило групп (вариант 1, выбран владельцем)

Группы вычисляются автоматически, явного поля `parent` пока нет. Реализовать в одном модуле (например,
`backend/app/domain/doc_tree.py`) с unit-тестами:

1. **Системы-источники** — документы типа `source`. Название системы = часть заголовка до «:» («ARIS:
   условная модель…» → «ARIS»). Ключ системы — из тега `sys-<key>` этого документа.
2. **Интеграции** (`integration`):
   - группа = система первой связи `consumes`, цель которой — документ `source`;
   - иначе — система первого тега документа, совпадающего с ключом системы;
   - иначе — «Общие правила».
3. **Стандарты** (`standard`): тег `template` или `шаблон` → «Шаблоны документов», иначе «Регламенты и
   качество».
4. Остальные разделы — без групп (документы прямо в разделе).
5. Группа из одного документа допустима.

На демо-данных правило даёт:
- ARIS — 8;
- CATIA — 2;
- CRM — 1;
- ERP — 1;
- Data Catalog — 1;
- Общие правила — 6.

Это проверено; ARIS включает расписание и lineage по тегу `aris`. Макет показывает группы условно —
верна эта раскладка.

`systems` у документа: системы из связей `consumes` / `produces` с целями типа `source`, плюс системы по
тегам; без повторов, в порядке появления.

Возможность явного `parent` в метаданных на будущее — не делать сейчас, но код дерева должен позволить
добавить его как более приоритетный источник группы без переделки.

### Прочее

- В `GET /api/documents` (элементы списка) добавить `summary` и `systems` — необязательные поля.
- Существующие контракты не менять.

## 5. Сохранить

Существующие возможности каталога не терять:
- поиск с подсветкой и причинами совпадения;
- фасеты (теперь в фильтрах таблицы и дерева);
- уведомление о состоянии индекса;
- демо-пометки;
- источник документов;
- переход на карту.

## 6. Проверка

- pytest:
  - правило групп на демо-данных (точная раскладка из §4);
  - пустые и неизвестные типы;
  - права доступа у `/api/documents/tree`;
  - `attention`.
- vitest:
  - дерево (клавиатура APG, раскрытие, фильтр, восстановление из URL);
  - список (сортировка, статус только у неутверждённых);
  - предпросмотр (загрузка, ошибка);
  - обзор (числа на демо-данных, клик по клетке ставит фильтры таблицы);
  - таблица (сортировка, фильтры, «Только требующие внимания» = 12).
- Playwright (desktop и mobile):
  - дерево → ARIS → документ → предпросмотр → «Открыть»;
  - «Требуют внимания» = 12;
  - обзор → клетка «Интеграции / Черновики» → таблица с 2 строками;
  - сортировка таблицы;
  - телефон: дерево → список → документ.
- Скриншоты 1440×900 и 390×844, светлая и тёмная темы, сверка с `screens/design/`.
