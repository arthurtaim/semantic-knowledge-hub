# Задание для Claude Code: планировщик v2 — Гант, масштабы, список задач

Ты начинаешь без контекста прошлых сессий. Всё нужное — в репозитории и в папке `planner-v2-handoff/`.
Работай самостоятельно, малыми срезами: изучи, реализуй, проверь, закоммить, отчитайся.

## Цель

Страница проекта (`/projects/:key`, M6 «Работа») перегружена, а диаграмма Ганта плохо читается:
- шапка съедает около 400 px;
- стрелки идут по подписям;
- на «Месяцах» диаграмма занимает треть ширины, а подписи обрезаются;
- нет масштабов «Квартал», «Год» и «Вписать»;
- в «Списке» выпадающий список в каждой ячейке.

Сделать по макетам (`screens/design/`) и спецификации `specs/PLANNER_V2.md`:
1. Компактный каркас страницы проекта: верхняя панель, строка проекта, один ряд фильтров и управления видом.
2. Гант:
   - масштабы День / Неделя / Месяц / Квартал / Год / «Вписать»;
   - адаптивная двухрядная шкала;
   - подписи без наложений;
   - стрелки по промежуткам с выделением связей выбранной задачи;
   - спокойные цвета статусов;
   - меню «Вид».
3. Список: обычные ячейки с редактированием по клику вместо `<select>`, группировка.

**Только фронтенд.** API, модель данных, серверный планировщик и поток «предпросмотр → применить» не менять.
Ручные сроки родителя (§9 спецификации) и критический путь — следующие задачи, не эта.

## 0. Ветка — первым делом

1. `git status --short`. Допустимы только неотслеживаемые папки владельца: `Claude outputs/`, `m6 copy/`,
   `planner-v2-handoff/`. Если есть изменённые отслеживаемые файлы — остановись и сообщи.
2. `git switch main && git pull --ff-only origin main`, затем `git switch -c feature/planner-v2`.
3. Если за время работы обновится `main` — влей `main` в свою ветку (merge, не rebase), разреши конфликты,
   проверь тесты.
4. Запрещено:
   - `git add -A` и `git add .`;
   - коммит папок владельца;
   - merge в `main` и другие ветки;
   - force push.
5. Первый коммит: скопируй `planner-v2-handoff/` в `docs/ui-v2/planner/` (с PNG и `design-source/`). Сообщение
   коммита: `docs(ui-v2): planner handoff`.

## 2. Срезы (по порядку; каждый срез — отдельный коммит с тестами)

1. **Логика без UI** в `lib/work.ts` (или `lib/gantt/`), с юнит-тестами (§8 спецификации):
   - масштабы `quarter`, `year`, `fit`, обратная совместимость `?zoom=`;
   - выбор единиц шкалы и подписи;
   - маршрут стрелок;
   - решение о подписи (внутри / справа / нет / метка вне окна);
   - режим связей «Авто».
2. **Каркас страницы проекта:**
   - верхняя панель;
   - строка проекта;
   - плашка режима — подсказкой, когда запись разрешена, и видимой, когда запрещена;
   - ряд фильтров с «Ещё» и чипами;
   - элементы вида справа.

   Общий для трёх видов.
3. **Гант, отрисовка:**
   - токены статусов (светлая и тёмная темы);
   - полосы, вехи, просрочка;
   - сводные задачи «скобкой» по подзадачам (§3.4);
   - шкала;
   - метка и линия «сегодня»;
   - слои в порядке §3.6;
   - подписи по §3.5.
4. **Гант, масштаб и связи:**
   - сегменты и «Вписать»;
   - `Ctrl`/`⌘` + колесо и щипок с точкой под курсором;
   - `Shift + 1`, `T`;
   - выбор задачи и выделение связей, наведение;
   - меню «Вид» с запоминанием;
   - обозначения внизу.
5. **Гант, раскладка:**
   - левая колонка с аватаром;
   - ширина перетаскиванием;
   - сворачивание колонки;
   - средняя ширина и телефон (§3.9).
6. **Список:**
   - ячейки без `<select>`, меню и календарь по клику и `Enter`, клавиши `1`–`4`;
   - сохранение с версией и конфликт — как в `InlineEdit`;
   - метки «ждёт» и «документы»;
   - группировка с `?group=`, колонки в «Вид».
7. **Доска:** каркас, единые значки статусов.
8. **Документация:** раздел «Планировщик v2» в `docs/UI_REDESIGN.md` — что сделано, отклонения от макетов,
   клавиатура, решения владельца из §7 спецификации.

## 3. Правила

- Русский UI, идентификаторы на английском. Никаких выдуманных чисел: все счётчики — из загруженных данных.
- Визуальная система UI v2:
  - только токены;
  - одна основная кнопка на вид («+ Задача»);
  - без капса и градиентов (штриховка просрочки — единственное исключение, это паттерн, а не украшение);
  - статус передаётся текстом и формой, не только цветом.
- Без новых зависимостей. Диаграмма остаётся своей SVG/DOM-отрисовкой. Если без зависимости не обойтись —
  остановись и спроси.
- Сохранить всё, что есть:
  - перетаскивание и клавиатуру полос (WCAG 2.5.7);
  - предпросмотр последствий и «Применить»;
  - пул «Без дат»;
  - нарушения связей;
  - виртуализацию строк;
  - режим только для чтения;
  - фильтры и их URL;
  - панель задачи по `?task=`.
- Тесты, которые опираются на старую разметку, обновлять в том же коммите с объяснением. Покрытие не
  уменьшать.
- Производительность: для проекта на 500 задач перерисовка при смене масштаба укладывается в 100 мс. Ширина
  текста подписей меряется с кешем, без чтения раскладки DOM в цикле.
