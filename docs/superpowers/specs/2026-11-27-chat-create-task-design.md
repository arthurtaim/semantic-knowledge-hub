# Создание задачи из чата и даты из запроса — дизайн

Дата: 2026-11-27. Статус: на согласовании у владельца (вопросы рецензента разобраны). Ветка: `feature/skh-chat-create-task` (от `main`
`5846bf0`).

## 1. Зачем

Сейчас из чата ассистента нельзя просто создать задачу. Единственный путь — вручную выбрать навык «Составить план
задач», выбрать проект, получить предложение плана (WAP), перейти в проект и нажать «Создать задачи»: пять шагов на одну
задачу. Без выбранного навыка фраза «создай задачу …» уходит в обычный ответ по базе знаний, и ассистент по своей
политике отвечает, что задачи из чата не создаются.

Второй дефект: даты, которые человек явно называет в запросе («до 5 декабря»), теряются, и их приходится вводить
вручную. Причина — правило M6: в инструкции навыка плана написано «не ставь даты», сервер отбрасывает даты от модели
(`_FORBIDDEN_TASK_KEYS` в `adapters/ai/work_protocol.py`, замечание «Модель указала даты — отброшено»), а срока
(`due_date`) у задач плана нет вообще.

Владелец выбрал вариант A (см. §4): в чате появляется черновик задачи в виде карточки-формы, человек проверяет его и
создаёт задачу одной кнопкой.

## 2. Цели, не-цели, анти-цели

Цели:
- **G1.** Навык «Создать задачу» (`create_task`). Человек выбирает его сам или ассистент запускает его автоматически,
  если фраза просит создать задачу.
- **G2.** Ответ — карточка-черновик. Поля заполнены из фразы. Недостающие поля подсвечены, и ассистент подсказывает:
  выбрать проект, название, описание (или берёт предложенное ассистентом), срок, даты, исполнителя. Человек правит
  карточку и нажимает «Создать задачу».
- **G3.** Если человек сразу указал всё нужное, черновик полностью готов, и остаётся только проверить и нажать кнопку.
- **G4.** Даты, названные человеком, сохраняются — и в карточке, и в навыке «Составить план задач».
- **G5.** Навык «Составить план задач» остаётся как есть: им планируют и уточняют несколько задач по документам.

Не-цели:
- Несколько задач, зависимости и подзадачи через карточку — это навык плана.
- Изменение существующих задач — это навык «Предложить изменения задач» (WCP).
- Изменение прав, ролей и модели доступа.
- Поиск по базе знаний и цитаты документов в ходе «Создать задачу».

Анти-цели (провал, даже если формально работает):
- Задача создаётся словами в чате («да», «создавай») или без клика человека.
- Дата, проект или исполнитель, придуманные моделью, попадают в задачу без того, чтобы человек их видел и подтвердил.
- Ассистент подставляет проект, который человек не называл и не выбирал.
- Автозапуск срабатывает на обычные вопросы о задачах («как создать задачу в Jira?», «какие задачи просрочены?») и мешает
  получить ответ.

## 3. Ограничения

- `AGENTS.md`:
  - AI предлагает, человек решает;
  - слова в чате ничего не применяют;
  - права проверяются на сервере;
  - извлечённый текст — данные, а не инструкции;
  - провайдер нейтрален (mock офлайн по умолчанию, GigaCode-ready);
  - слабая модель: короткие строгие JSON-ответы.
- **Режим mock (без модели) должен работать.** Создание задачи — обычная операция, ей модель не нужна.
- **ADR-045 меняется точечно.** Пути записи в `/api/assistant/ask` и инструмента записи у модели по-прежнему нет.
  Задачу создаёт кнопка карточки — тот же маршрут `POST /api/projects/{key}/tasks`, что у формы «Новая задача» в
  проекте, с теми же правами, журналом и идемпотентностью. Фиксируется новым ADR-049.
- Миграции схемы нет. Новые поля плана — необязательные ключи в JSON предложения (`StoredTask.from_json` читает старые
  записи без них).
- `make knowledge-eval` должен остаться 210/216 без флипов. Ни один из 216 вопросов не должен попадать под автозапуск.
- Существующий тест «промпт плана без уточнения неизменен байт в байт» намеренно обновляется: промпт меняется (§5.6).

## 4. Подходы

| | Подход | Плюсы | Минусы | Решение |
|---|---|---|---|---|
| **A** | Карточка-форма, создание обычным `create_task` | работает без модели; все поля задачи (срок, даты, исполнитель); одна известная операция; меньше движущихся частей | в журнале нет отдельного «предложения AI»: записано, что задачу создал человек (так и есть) | **выбран владельцем** |
| B | Та же карточка поверх WAP из одной задачи, кнопка применяет WAP из чата | буквально «навык плана в удобном UI», хранимая история предложения | без модели не работает; WAP устаревает при любой правке проекта между черновиком и кликом (409); WAP надо учить сроку и исполнителю; больше переделок | отклонён |
| C | Пошаговый диалог: ассистент спрашивает поля по одному | разговорно | 4–5 ходов на задачу, хрупко со слабой моделью, сложно хранить состояние | отклонён |

## 5. Решения

### 5.1 Навык `create_task`

- `SkillDefinition`:
  - `id="create_task"`, `name="Создать задачу"`;
  - описание: «Подготовит черновик задачи из вашей фразы; задачу создаёте вы кнопкой в карточке»;
  - `access="draft"`, новый runner `work_task`;
  - `requires_project=False` (проект можно выбрать в карточке);
  - доступен и в mock.
- Каталог помечает навык недоступным с причиной в трёх случаях:
  - модуль задач выключен;
  - нет глобального `Action.create_task`;
  - режим только просмотра (открытая ссылка, `X-SKH-Exposure: public`).
- *Решение строителя.* При `AI_PROVIDER=disabled` навык недоступен, как и все навыки: в этом режиме чат работает как
  поле поиска, без навыков. В mock навык работает.
- Права проверяются тем же путём, что у других навыков Work: `global_actions(skill)` = `{create_task}`, `work_denied`,
  `WorkPrincipal` из `api/work.py::work_principal`.
- Композер: при выбранном навыке показывается строка «Проект» из M7 (без автоподстановки, необязательна для этого
  навыка), без строки «Задачи». Выбранный в композере проект попадает в черновик.

### 5.2 Автозапуск

- Решение принимает сервер в `SkillRunner.plan()`, только когда клиент не прислал `skill_id` (`None`). Явный
  `skill_id`, в том числе `answer`, автозапуск отключает.
- Правило детерминированное, в отдельной функции домена (`app/domain/task_intent.py`), без модели, работает в mock.
  Срабатывает, если:
  - в первых шести словах есть повелительный глагол (`создай/создайте/заведи/заведите/добавь/добавьте/поставь/
    поставьте/оформи/оформите`) и сразу за ним, допуская одно-два слова между, слово `задачу` (единственное число);
  - или текст начинается с `задача:` / `новая задача`.
- *Решение строителя.* Множественное число («создай задачи …») и списки из нескольких строк автозапуск НЕ включают:
  карточка — это одна задача, а навык плана по решению владельца вызывается вручную. Такой запрос получает обычный
  ответ.
- Не срабатывает:
  - на вопросы: начало с `как/где/почему/зачем/можно ли/что/какие/какая/какой/сколько`, или текст кончается на `?`;
  - если к сообщению приложены файлы. Документ в контексте (панель ассистента документа, «@») и выделенный фрагмент
    автозапуск не блокируют: задача свяжется с документом (§5.4);
  - если навык `create_task` недоступен этому человеку (тогда обычный ответ).
- Сработавший автозапуск виден: в ответе `skill` = «Создать задачу», а на карточке кнопка «Ответить как обычно». Она
  повторно отправляет тот же вопрос с явным `skill_id="answer"`.
- Тесты правила: списки положительных и отрицательных фраз, включая все 216 вопросов gold-набора (ни один не должен
  сработать).

### 5.3 Черновик на сервере (`TaskDraftService`)

Вход: принципал, текст запроса, необязательный `project_key` из композера. Ничего не записывает. Шаги:

1. **Серверное извлечение — всегда, без модели:**
   - даты (§5.5);
   - проект — упоминание ключа (`RAG`) или точного названия среди проектов, видимых человеку и открытых для
     `create_task` (не архивных);
   - исполнитель — однозначное совпадение имени или фамилии из каталога исполнителей (`/api/work/assignees`).
     *Решение строителя:* сравнение учитывает падежные окончания (общая основа не короче 4 букв: «на Лебедеву»,
     «Анне» → «Анна Лебедева (демо)»), совпадение должно быть единственным. В локальном режиме каталог общий (так
     работает стенд). В командном режиме (`membership`) сравнение идёт по id и отображаемому имени участников проекта, а
     до выбора проекта исполнитель не определяется. Нераспознанное упоминание сохраняется как текст `assignee_hint` и
     показывается в карточке («Исполнитель из запроса: «Анне» — выберите»);
   - приоритет по словам: «срочно/критично» → `critical`, «высокий/важно» → `high`, «низкий/не срочно» → `low`.
2. **Модель — если провайдер умеет `draft_task`** (новая возможность `TaskDraftAIProvider` в `adapters/ai/base.py`,
   реализуют `openai_compatible` и `claude_cli`; mock и disabled — нет):
   - один вызов, новый вендор-нейтральный протокол `adapters/ai/task_draft_protocol.py`;
   - запрос передаётся как данные: в разделителях, через `redact_prompt_injection`;
   - строгий JSON: `{"title", "description", "project_hint", "assignee_hint", "priority", "due_quote", "start_quote",
     "end_quote", "assumptions"}`;
   - неверные типы → ответ модели отброшен целиком (черновик строится только из серверного извлечения, в карточке
     замечание «ассистент не смог разобрать фразу»), а не 502: карточка остаётся полезной;
   - ограничения: название ≤ 120 символов, описание ≤ 2000, ответ ≤ 16 КБ.
3. **Проверка и слияние** (правила одинаковые для всех полей):
   - **Дата от модели** принимается, только если её `*_quote` — дословный фрагмент запроса (сравнение без учёта регистра
     и лишних пробелов) и сервер сам разобрал этот фрагмент в дату (§5.5). Иначе дата отбрасывается с замечанием.
     Значение даты модель не задаёт — только цитату.
   - **Проект и исполнитель от модели** — подсказки. Принимаются, только если однозначно совпадают с разрешённым
     проектом или исполнителем; иначе поле пустое с замечанием.
   - Проект, выбранный в композере, главнее всего. Серверное извлечение и модель дополняют друг друга. Если они
     противоречат друг другу по одному полю, поле остаётся пустым с замечанием «уточните».
   - Без модели название = текст запроса без триггерной фразы и распознанных фрагментов (дат, проекта, исполнителя),
     обрезанный до 120 символов, с заглавной буквы. Описание пустое.
4. **Ответ.**
   - `AskResponse.task_draft: TaskDraft` (новое аддитивное поле):
     - значения полей: `project_key`, `title`, `description`, `priority`, `assignee_id`, `assignee_hint`, `due_date`,
       `start_date`, `end_date`;
     - `origin` по каждому полю: `request` (из фразы человека), `assistant` (предложение модели), `composer`
       (выбор в композере), `default`;
     - `documents` — документы из контекста запроса, видимые читателю в его снимке: `{document_id, title, revision}`
       (ревизия, которую видел человек; скрытый документ не попадает в черновик и ничего не раскрывает);
     - `missing` — обязательные пустые поля: проект и название;
     - `issues` — замечания `{field, code, message}`;
     - `auto_started: bool`.
   - Текст ответа короткий и составлен сервером: «Проверьте черновик задачи и нажмите «Создать задачу»» или «Не хватает:
     проект». Свободного пересказа модели нет, ответ одинаков во всех режимах.
   - История чата хранит ответ целиком, вместе с черновиком.

### 5.4 Карточка в чате (`AskTaskDraft`)

```
Черновик задачи — проверьте и создайте
  Проект       [ выберите проект ▾ ]          ← не указан
  Название     Обновить витрину продаж         из вашего запроса
  Описание     [ …текст… ]                     предложение ассистента
  Срок         05.12.2026                      из вашего запроса
  Даты плана   [ начало ] — [ окончание ]
  Исполнитель  [ не назначен ▾ ]
  Приоритет    [ средний ▾ ]
  (замечания сервера, если есть)
               [ Создать задачу ]  [ Ответить как обычно ]
```

- Поля карточки:
  - **Проект** — список проектов, где человек может создавать задачи, без архивных; без предвыбора, если проект не
    назван и не выбран;
  - **Название** — обязательно;
  - **Описание** — необязательно, с меткой «предложение ассистента», если его предложила модель;
  - **Срок** (`due_date`);
  - **Даты плана** — начало и окончание, оба или ни одного; окончание включительно в интерфейсе, на сервер уходит
    `end_exclusive`;
  - **Исполнитель** — из `/api/work/assignees`;
  - **Приоритет**.
- Подсветка и подсказки: пустые обязательные поля подсвечены, рядом подсказка («Выберите проект»). Кнопка «Создать
  задачу» неактивна, пока нет проекта и названия. Если указано только начало, окончание подсвечено как недостающее.
- Метки происхождения («из вашего запроса», «предложение ассистента») показывают, откуда значение; правка поля меняет
  метку на «изменено вами».
- **«Создать задачу»:**
  - отправляет `POST /api/projects/{key}/tasks` с `TaskCreate`, `client_request_id` один на карточку, повторный клик
    блокируется;
  - `201` → карточка превращается в «Задача KEY-N создана» со ссылкой «Открыть задачу»;
  - `422` → ошибка показывается у нужного поля (по `details.field`), например выходной день или неверный исполнитель;
  - `403` → «Нет прав на создание задач в этом проекте»;
  - `404` → «Проект недоступен».
- **Связь с документом (решение владельца).** Если в черновике есть документы из контекста, карточка показывает по
  флажку «Связать с документом «…»» на каждый, включённый по умолчанию. После `201` карточка создаёт связи
  существующим маршрутом `POST /api/tasks/{id}/links` (документ + ревизия из черновика).
  - Маршрут связи требует `Action.edit_task`. Если связь не создалась (нет прав, документ стал недоступен, сбой сети),
    задача остаётся, а карточка пишет: «Задача создана, связь с документом не добавлена — добавьте её в задаче».
    Повторить связь можно кнопкой «Добавить связь» на той же карточке.
  - Связь задачи с документом — это не связь графа знаний (инвариант M6).
- Если навык запустился автоматически, на карточке есть кнопка «Ответить как обычно».
- Слова в чате ничего не создают: следующая реплика — новый ход, черновик остаётся как был.
- Панель ассистента документа (компактная) показывает ту же карточку. Если так не помещается, строитель может заменить
  её ссылкой «Открыть в ассистенте».

### 5.5 Даты из текста (`app/domain/ru_dates.py`, общий модуль)

- Форматы:
  - `5 декабря [2026]`, `5 дек`;
  - `05.12`, `05.12.26`, `05.12.2026`;
  - `2026-12-05`;
  - `сегодня`, `завтра`, `послезавтра`;
  - `через N дней|недель|рабочих дней`;
  - дни недели: `в/до/к понедельник…воскресенье` в нужном падеже — ближайший будущий такой день; если сегодня этот же
    день недели, то через неделю.
- Маркеры → поле:
  - `до / к / не позднее / срок / дедлайн` + дата → `due`;
  - `с X по Y`, `X–Y` → `start` + `end`;
  - `с / начать / начиная с / стартовать` + дата → `start`.
- Год: дата без года — ближайшая будущая (сегодня или позже).
- «Сегодня» — `WorkService._today(timezone проекта или по умолчанию)`; функции модуля принимают `today` явно (чистые,
  тестируемые).
- Разобранная дата проверяется на допустимый диапазон (`check_work_date`). Выходной день для начала или окончания плана
  — замечание в черновике. Окончательную проверку делает сервер при создании.
- Модуль возвращает и найденный фрагмент текста: по нему строится название без дат, по нему же проверяются цитаты
  модели.

### 5.6 Навык «Составить план задач»: даты из запроса

- Правило 4 промпта меняется: «Исполнителей не назначай. Даты не придумывай. Если человек В ЗАПРОСЕ назвал срок или
  даты задачи, укажи `due_quote` / `start_quote` / `end_quote` — дословный фрагмент запроса. Если назван старт всего
  плана — `plan_start_quote`.»
- Парсер плана принимает новые необязательные ключи. Прежнее поведение для голых значений (`due_date: "2026-12-05"`
  без цитаты) сохраняется: значение игнорируется с замечанием.
- Проверка (`app/work/ai.py`): цитата должна быть фрагментом текста запроса или уточнения и разбираться в дату через
  `ru_dates`. Иначе дата отбрасывается с замечанием.
- Новые необязательные поля в JSON предложения:
  - у `StoredTask`: `due_date`, `fixed_start`, `fixed_end`;
  - у предложения: `suggested_start` — им заполняется выбор «Начало плана» в проверке.
- Расписание:
  - задачи с периодом из запроса сохраняют свои даты и создаются с `date_locked=true`;
  - остальные считаются от начала плана, оценок и FS-зависимостей, как сейчас;
  - преемник закреплённой задачи начинается после неё;
  - срок (`due_date`) Гант не двигает;
  - противоречие (закреплённая задача кончается позже закреплённого начала преемника) — замечание, а не ошибка.
- *Решение строителя* — неполные даты:
  - есть только начало и есть оценка → начало закреплено, окончание считается по оценке;
  - есть только «по X» → это срок (`due_date`);
  - у вехи одна дата → веха в этот день;
  - начало плана не выбрано → закреплённые задачи сохраняют свои даты, их преемники ставятся после них, остальные
    задачи остаются без дат, как сейчас.
- Проверка WAP (`WorkPlan.tsx`): колонка «Срок» и закреплённые даты с меткой «из вашего запроса». *Решение
  строителя:* срок можно править; закреплённый период можно только снять (тогда задача считается как обычная), а
  править даты — на Ганте после создания. `WorkProposalEdits` получает по задаче правку `due_date` и флаг
  `unpin_dates`.
- `apply_task_plan` передаёт `due_date`, а для закреплённых задач — `start_date`, `end_exclusive` и `date_locked`. Все
  даты проверяются, как сейчас.

### 5.7 Безопасность и политика ассистента

  аудитом `task_created`.

  нет.

## 6. Проверки

- **Unit:**
  - `ru_dates` (таблица форматов, год, дни недели, относительные даты, диапазоны);
  - `task_intent` (положительные и отрицательные фразы плюс 216 вопросов gold-набора);
  - протокол черновика (строгие типы, лимиты, разделители);
  - протокол плана с цитатами дат.
- **Сервис и API:**
  - всё указано → полный черновик;
  - нет проекта → `missing`;
  - дата с выдуманной цитатой отброшена;
  - скрытый или архивный проект не подставляется;
  - неизвестный исполнитель → замечание;
  - внедрение в запросе ничего не меняет;
  - mock → черновик из серверного извлечения;
  - автозапуск включён / выключен явным `skill_id` / выключен при вложенных файлах / включён при документе в контексте;
  - в черновик попадают только видимые читателю документы контекста, с их ревизией;
  - режим только просмотра → навык недоступен, автозапуска нет;
  - план: срок и закреплённый период сохраняются, выдуманные даты отброшены, уточнение тоже переносит даты.
- **Frontend (vitest):**
  - состояния карточки;
  - обязательные поля и подсветка;
  - тело `POST` при создании;
  - двойной клик пишет один раз;
  - ошибки 422/403/404 у полей;
  - связь с документом создаётся после задачи; если связь не создалась, задача остаётся, есть «Добавить связь»;
  - «Ответить как обычно»;
  - колонка «Срок» в проверке плана.
- **E2E (scripted):**
  - фраза → карточка → «Создать задачу» → задача видна в проекте;
  - фраза со всеми полями → один клик;
  - автозапуск и «Ответить как обычно»;
  - телефон 375 px.
- **Регрессия:** `make check`, `make work-eval`, `make knowledge-eval` (210/216, 0 флипов), прежние E2E.
